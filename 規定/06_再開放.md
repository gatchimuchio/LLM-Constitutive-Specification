# 再開放

## 目的

正本を版内では強く固定しつつ、現在の分類・条件数・境界・語彙を対象そのものへ昇格しない。

## 1. 再開放原則

射程内反例、新構造、下流での反復不整合、観測誤りが出た場合、局所文言だけで帳尻を合わせず、必要なら成立条件そのものまで戻る。

## 2. 再開放条件

少なくとも次を契機とする。

- 言語模型性四条件で実在LMを記述できない。
- 四条件を満たすが明らかに言語模型ではない反例が成立する。
- 模型成立条件と識別監査条件が再び混線している。
- 構成観測軸を普遍構成条件へ誤昇格している。
- 構成再現の元模型相対性では説明できない反例が出る。
- 形成済み模型状態と形成済み関係の境界が破綻する。
- retrieval / memory / tool等の模型境界が部品名分類で破綻する。
- 固定した規模尺度では実在の「large」用法を記述できない。
- 新しい非自己回帰・非ニューラル・混成模型が現行語彙で損失なく記述できない。
- 下流再構成物の失敗が、実装ではなく上位定義・射影の誤りで説明される。
- 既存出典・実装・weight等の証拠が撤回・破損する。

benchmark点数だけを理由に正本を変更しない。ただし点数失敗を反例探索の入口にすることはできる。

## 3. 再開放範囲

反例が出た場合、次を順に監査する。

1. 観測誤り
2. 版・対象同一性
3. 対象言語体系 / 言語状態域
4. 言語模型性四条件
5. 識別監査条件
6. 模型境界
7. 形成済み模型状態 / 実行作用
8. 機能再現の定義
9. 構成再現対象プロファイル
10. 構成不変量の因果認定
11. 規模プロファイル
12. 規定体系全体

必要な段階まで戻る。

## 4. 条件数を保守しない

過去版で五条件・七条件・三面と定めたことを、新版でも同じ数を維持する理由にしない。

条件数は対象の構造から結果として決まり、履歴互換性のために対象を条件数へ合わせない。

## 5. 旧版の扱い

v1〜v4の規定・観測・誤りはGit履歴と観測資料へ保持する。

旧条件を再利用する場合、現行版の帰属階層へ再分別する。

## 6. 変更履歴

改訂時は最低限次を残す。

- 旧版 / 新版
- 変更した前提
- 捨てた条件・残した条件
- 独立観測・一次資料
- 下流逆算監査を使った場合の位置づけ
- 影響範囲
- 旧判定への影響

## 7. 現行版

現行版は **2026-08-28-成立規定-5** とする。

状態は **局所安定正本 / 再開放可** とする。
