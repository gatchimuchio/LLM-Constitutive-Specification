# 運用境界

## 目的

言語模型成立の中核、言語対応、表出、実行系、形成履歴、利用外周を同じ階層へ横並びにしない。

## 1. 模型中核

模型中核で問うのは、文脈付き内部言語状態に応じて、対象言語関係に対応する形成差を生じさせる模型形成関係があるかである。

特定の物理層数・部品数は要求しない。

## 2. 言語対応

対象自然言語側と模型内部側を同じ対象について比較・追跡できるようにする対応境界。

入力側と出力側を持ち得る。

実装例としてtokenizer、vocabulary、byte mapping、special token、出力head等があるが、名称を普遍必須にしない。

言語対応は単なる外部表示処理とは限らない。対応を無関係に変更すると模型の言語関係同一性が壊れる場合がある。

## 3. 形成差と表出を分ける

模型形成関係が生じさせる形成差と、実際の外部言語結果を確定する表出作用を分ける。

同じ形成差から、argmax、sampling、top-p、beam、決定規則、拡散反復等の条件により外部結果が変わり得る。

これらの名称を普遍必須にしない。

## 4. 運用閉包

運用型の生成言語模型系では、概念上次の閉路を確認する。

```text
外部自然言語
→ 言語対応
→ 文脈付き内部言語状態
→ 模型形成関係
→ 形成差
→ 表出作用・反復
→ 外部言語結果
```

この閉路を物理構成要素数として読まない。

一つの機構が複数の役割を担ってよい。複数機構が一つの役割を共同で担ってよい。

## 5. 実行系と模型物を分ける

模型物が保存されていても、実行環境の故障・依存欠損・未対応計算機等により現在実行できない場合がある。

運用故障を模型形成関係の消失へ自動帰属しない。

逆に、APIサービスが動くことだけから内部模型物の構造を推測しない。

## 6. 形成履歴

次は模型がどう作られたかの履歴として記録する。

- 事前学習
- 後学習
- 選好学習
- 強化学習
- 蒸留
- 手書き
- コンパイル
- 探索
- 進化
- 混成

形成履歴は能力・同一性・再現性の説明に重要だが、実行時の模型形成関係そのものとは分ける。

「学習済みだから言語模型」「手書きだから言語模型ではない」という判定をしない。

## 7. 利用外周

次を模型能力へ自動帰属しない。

- 検索サービス
- 外部道具
- 長期記憶サービス
- 安全分類器
- 承認機構
- ルータ
- エージェント反復
- 複数模型の協調
- 製品UI
- 配備基盤

候補系の成立に不可分であることが観測された場合だけ境界を再開放する。

## 8. モダリティ

本版の中心は自然言語である。

画像・音声・動画等が追加条件として入る場合、自然言語関係と他媒体関係を分ける。

「マルチモーダルだから同じ模型本体」「画像能力があるから言語形成能力も同じ機構」という逆算をしない。

## 9. 同一性

最低限次を分ける。

### 物理同一性

重み、規則、表、グラフ、コード、設定等の再現上の同一性。

### 言語関係同一性

言語対応と模型形成関係が、対象自然言語に対して同じ関係を保持する同一性。

本規定の中心はこちら。

### 運用同一性

表出規則、停止条件、会話整形、乱数条件等まで含む実行挙動上の同一性。

## 10. 旧規定の再配置

旧Layer-0で同格に置いていた観測は、現行では概ね次へ分かれる。

- token / symbol space → 言語対応
- context state → 模型形成関係の条件側
- transform → 模型形成関係の実装作用
- learned / parameterized → 形成履歴・模型物形式
- conditional output → 形成差の実装
- fitting objective → 形成履歴
- decoding / emission → 表出作用・運用閉包

旧観測自体を削除せず、帰属階層を訂正する。
