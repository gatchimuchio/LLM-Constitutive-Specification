# 運用境界

## 目的

模型中核、言語対応、形成済み模型状態、実行作用、生成運用、実行環境、利用外周を、部品名だけで固定分類せず、同一性と因果関与から分ける。

## 1. 模型中核

模型中核で問うのは、`02_大規模言語模型成立.md` の四条件がどの模型境界で成立しているかである。

- 言語状態域
- 条件付き言語差形成
- 構成再利用
- 言語状態接続

特定の物理部品数・層数・ニューラル構造は要求しない。

## 2. 形成済み模型状態

現在の模型同一性に持続的に属し、実行時挙動へ作用する状態を形成済み模型状態とする。

weight、rule、table、graph、index等の方式名だけでは内部・外部を決めない。

特定の意味関係が保持されていると観測できた部分のみを局所的に形成済み関係と呼ぶ。

## 3. 実行作用

形成済み模型状態と入力・文脈を使い、実行時に内部差・成立差を形成する作用。

Attention、RNN、diffusion step、retrieval、rule evaluation等は実装形であり、名称だけで模型中核性を決めない。

## 4. 模型境界の判定

ある要素 `X` が模型の一部かを、少なくとも次で監査する。

1. **同一性固定** — `X` が模型版・artifact・正式inference contractの一部として固定されるか。
2. **実行必須性** — `X` 無しでは、宣言した対象範囲で言語模型性四条件の同じ関係を成立させられないか。
3. **形成結合** — `X` が他の模型部分と共同学習・共同最適化・共同コンパイル等で形成されているか。
4. **介入影響** — `X` の除去・交換・固定により条件付き言語差形成や構成再利用の関係が系統的に変わるか。
5. **展開任意性** — 利用者が模型同一性を保ったまま任意交換できるdeploy後部品か。

物理ファイル位置・別process・別serviceであることを、そのまま模型外の根拠にしない。

## 5. retrievalの境界

retrievalは一律に利用外周としない。

REALMのようにretrieverがpre-trainingから共同最適化され、推論時にもretrieve-then-predict関係の一部として必要な場合、retrieverと対象corpus/indexは模型境界へ寄り得る。

RETROのようにretrieval databaseへの参照が模型architectureの推論関係へ組み込まれる場合も同様である。

一方、既存模型へ任意のWeb検索toolを後付けし、そのtoolを外しても同じ模型自体が成立する場合、通常は利用外周へ寄る。

## 6. 言語対応

対象言語状態と模型内部状態を比較・追跡する境界。

Tokenizer、vocabulary、byte mapping、adapter等が模型同一性に含まれる場合も、外部interfaceとして交換可能な場合もあるため、部品名ではなく模型境界判定に従う。

## 7. 形成履歴

training、post-training、distillation、hand-writing、search、compilation、evolution等は形成履歴である。

形成履歴は現在の模型状態を説明するが、実行時作用そのものではない。

## 8. 生成運用

模型が形成した成立差から外部言語状態を一つへ確定する運用を、言語模型性と分ける。

argmax、sampling、beam、iterative unmasking等は生成運用または実行作用の一部になり得る。どちらかは模型同一性と対象範囲で決める。

## 9. 実行環境

模型物が存在しても、hardware、runtime、dependency、credential等の欠損で実行できない場合がある。

実行環境故障を模型性の消失へ自動帰属しない。

## 10. 利用外周

次は典型的には利用外周へ寄るが、部品種別だけで確定しない。

- 任意追加の検索tool
- 製品UI
- safety classifier
- routing service
- agent loop
- long-term task memory
- multi-model orchestration
- approval flow

対象系の模型同一性へ不可分に組み込まれていることが観測された場合は再分類する。

## 11. system能力

模型とその外周を含むsystem全体の能力を、模型単体能力へ無言加算しない。

同時に、模型境界に含まれるretriever・memory等を「外部部品だから」と無言減算もしない。

## 12. multimodal境界

画像・音声等が入る場合、modality encoder / adapter / language coreの同一性関係を観測する。

language coreを固定したadapter追加型も、共同形成型もあり得る。`multimodal = 同一模型中核` と自動判定しない。

## 13. 同一性

### 物理同一性

weight、rule、table、graph、index、code、setting等の再現上の同一性。

### 言語模型同一性

言語模型性四条件を成立させる模型側関係が、同じ対象言語状態域について保たれる同一性。

### 運用同一性

sampling、停止、UI、外部tool、session state等まで含む実行挙動上の同一性。

## 14. 機能再現と構成再現の境界

同じ言語模型同一性を別構成で実現しても、機能再現は成立し得る。

構成再現を主張する場合だけ、元模型の構成不変量を追加で保存する。

したがって、

```text
機能再現 != 構成再現
```

であり、非ニューラル代替がTransformer内部作用を再現しないこと自体は機能再現の失敗理由にならない。
