# 観測と判定

## 目的

模型そのものの成立条件と、その成立を外部から確認する監査条件を分ける。さらに、機能再現と構成再現を別軸で判定する。

## 1. 監査対象を先に固定する

候補模型を見る前に、最低限次を固定する。

- 対象模型・版
- 対象言語体系
- 言語状態域
- 文脈条件
- 比較する言語状態
- 対象範囲 / 対象外範囲
- 監査時点

これは模型の成立条件ではなく、監査の循環を防ぐ条件である。

## 2. 言語模型性四条件の監査

### 2.1 言語状態域監査

模型が固定ラベル・固定recordだけでなく、宣言した言語単位から構成される状態を対象にしているか確認する。

### 2.2 条件付き言語差形成監査

文脈・入力の差を系統的に変え、言語状態域上の成立差が対応して変わるかを見る。

単一例で確定しない。

### 2.3 構成再利用監査

設計・test fixture・knowledge tableで完全個体として列挙していない組合せへ、同じ模型側作用が再利用されるかを見る。

### 2.4 言語状態接続監査

内部差が、言語状態の選択・形成・補完・復元・変換・更新へ接続するかを見る。

固定タスクラベル・数値scoreだけを返す系では、基底模型に別の言語状態接続が存在するかを分けて確認する。

## 3. 識別監査の最低証拠

現行版では、言語模型性を局所安定と採用するため次を要求する。

1. **独立対象固定**
2. **言語対応**
3. **差分追従**
4. **複数対照への再利用**
5. **未列挙構成監査**
6. **再現性**

これらを「六つの模型部品」と読まない。

## 4. anti-lookup監査

構成再利用を主張する場合、完全個体lookupで説明できる可能性を監査する。

有効な対照例:

- 未列挙の単位組合せ
- 語順・条件・極性を変えた対照
- 同じ部品から新しい構成を作る対照
- 既知個体名を別の同型個体へ置換する対照

巨大lookupを論理的に完全排除できない場合は、物理実装観測や形成物監査と合わせて判断する。

## 5. architecture横断監査

同一規定が異種言語模型へ適用できるか確認する。

最低限、次の系譜を対照集合に含める。

- causal decoder: Llama系
- masked bidirectional: BERT系
- encoder-decoder text-to-text: T5系
- recurrent: RWKV系
- masked diffusion: LLaDA / iLLaDA系
- retrieval-integrated: REALM / RETRO系

この横断で破綻する物理要件を普遍成立条件へ置かない。

## 6. 機能再現監査

別模型が元模型の機能を再現したと主張する場合、内部構造一致ではなく、対象言語関係について次を比較する。

- 入力差への追従
- 文脈差への追従
- 未列挙構成への再利用
- 成立差の方向・制約・選択の整合
- 対象外条件での差
- 再現性

benchmark点数は補助証拠であり、単一score一致だけで機能再現を確定しない。

## 7. 構成再現監査

構成再現は元模型相対で行う。

### 7.1 再現対象プロファイル

元模型ごとに、

- 対象能力
- 観測深度
- 状態・作用
- source code / config / weights / paperで直接観測できた差
- 未観測範囲
- 再現対象外

を固定する。

### 7.2 構成不変量監査

構成不変量へ昇格するには、存在確認だけでなく因果接続を要求する。

有効な証拠:

- ablation / disable
- state intervention
- component substitution
- same-family controlled comparison
- source implementationで明示された依存関係と実測の一致

### 7.3 出力類似から内部構成を逆算しない

閉鎖模型や内部未観測模型について、同じ出力・scoreだけから内部構成を推定しない。

この場合は機能再現まで主張でき、構成再現は未観測とする。

## 8. v3/v4観測軸の扱い

次は高能力LLM比較で有用な観測軸として保持する。

- 状態保持・輸送
- 状態遷移
- 未確定差・複数経路
- 寄与調整
- 再作用・再参照・再結合
- 局所/広域作用
- 深さ/幅方向作用
- 形成済み模型状態
- 終端遅延

しかし対象元模型で観測・因果確認されていない軸を、構成再現の必須条件へ自動追加しない。

## 9. 模型境界監査

retrieval、memory、adapter、router、tool等は部品名で分類せず、`04_運用境界.md` の模型境界判定を適用する。

外部serviceでも模型同一性へ不可分なら模型側へ寄り、同一process内でも任意deploy制御なら外周へ寄り得る。

## 10. 規模監査

大規模性は言語模型性成立後に別監査する。

固定三面を要求せず、規模プロファイルの尺度・比較集合・観測値を確認する。

## 11. 補助監査

必要に応じて次を使う。

- 保存追従
- 破壊追従
- 反実仮想
- benchmark
- perplexity / likelihood等の外部尺度
- human evaluation
- latency / memory / compute

特定指標を普遍成立条件にしない。

## 12. 状態語

- 局所安定
- 不適合
- 未観測
- 未確定
- 矛盾
- 保留
- 対象外
- 再開放要

## 13. 下流失敗からの逆算

MINIDORA等の下流物は上位規定の成立証人ではない。

一方、下流で反復する失敗は、次のどこが誤っているかを探す反例として利用できる。

1. 言語模型性四条件そのもの
2. 識別監査条件
3. 機能再現の射影
4. 構成再現対象プロファイル
5. 構成不変量の取り違え
6. 模型境界
7. 規模記述

**下流失敗を「実装が悪い」と先に固定せず、上位定義自体を再開放候補に含める。**
