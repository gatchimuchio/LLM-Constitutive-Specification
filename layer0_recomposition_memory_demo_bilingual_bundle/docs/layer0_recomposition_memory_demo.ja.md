# Layer-0 再合成デモ：LLM機能役割から作るメモリ機構

> ステータス：デモ成果物  
> スコープ：非LLM派生アーキテクチャ  
> 目的：Layer-0の機能役割を再合成することで、決定論的なメモリサブシステムを構成できることを示す。

---

## 1. このデモの目的

Layer-0定理は、現代的Large Language Modelに必要な最小機能役割を定義する。  
この結果には、もう一つの研究上の含意がある。

> LLMの機能コアを安定した役割へ分解できれば、それらの役割を隣接する非LLMシステムへ再合成できる。

このデモでは、その一例としてメモリサブシステムを示す。

対象システムは **LLMではない**。  
これは、LLMにおける読込・要約・文脈形成・出力という運用パターンを転用し、次を構成する決定論的アーキテクチャである。

- メモリ候補生成
- メモリ更新
- メモリ上書き／置換
- メモリ破棄
- コンテキスト再構成

目的はモデル性能ではない。  
目的は **アーキテクチャ転用可能性の提示** である。

---

## 2. 再合成マップ

| Layer-0役割 | LLMでの役割 | メモリシステムへの再合成 |
| --- | --- | --- |
| `TOKEN_OR_SYMBOL_SPACE` | 言語単位を表現する | イベントとメモリレコードを直列化可能な記録空間として扱う |
| `CONTEXT_CONDITIONING_STATE` | 過去文脈で出力を条件づける | ユーザー／プロジェクト／タスク文脈を保持し、記憶更新に使う |
| `LEARNED_PARAMETERIZED_TRANSFORM` | 文脈から出力面へ写像する学習済み変換 | 実運用ではLLM要約器／抽出器、このデモでは決定論的スタブ |
| `CONDITIONAL_LINGUISTIC_OUTPUT_SURFACE` | 条件付き出力候補を形成する | create/update/supersede/discard などのメモリ操作候補を形成する |
| `SEQUENCE_MODELING_OBJECTIVE_OR_EQUIVALENT_FITTING_CRITERION` | 系列に適合するための訓練目標 | 文脈予算内で将来有用な状態を残す保持目的へ置換する |
| `DECODING_OR_EMISSION_INTERFACE` | 観測可能なトークン／テキストを出力する | 永続メモリ書き込みとコンテキストブロックを出力する |

これは意図的な責任境界の移動である。

元のLayer-0役割は、あるシステムがLLMに該当するかを定義する。  
この再合成デモは、その役割を「一枚岩のモデル」ではなく、再利用可能なアーキテクチャ部品として扱った場合に何が作れるかを示す。

---

## 3. このデモが証明すること

このデモが示す主張は限定的である。

> Layer-0的な読込・要約・文脈条件づけ・出力の役割を再合成することで、最小の決定論的メモリサブシステムを構成できる。

証明しないこと：

- この決定論ヒューリスティックが優秀な要約器であること
- このシステム自体がLLMであること
- すべてのエージェントメモリがこの設計を使うべきであること
- タスク固有評価なしに意味的なメモリ品質を測定できること

証明対象は意味品質ではなく、**構造** である。

---

## 4. デモで示すライフサイクル

実行デモは小さなイベント列を処理する。

1. 永続すべきユーザー設定を観測する。
2. プロジェクト上の設計判断を観測する。
3. 一時メモを観測し、破棄する。
4. 後続イベントにより永続設定を更新する。
5. 古いメモリを superseded として扱う。
6. active メモリからコンテキストを生成する。
7. JSON証明書にライフサイクルと不変条件チェックを記録する。

期待される状態遷移：

```text
candidate -> active -> superseded
candidate -> discarded
active -> context block
```

ここで重要なのは次の点である。

> メモリはチャット履歴の塊ではない。要約され、出典を持ち、バージョン管理され、状態遷移を持つ制御対象である。

---

## 5. なぜエージェント設計で重要か

単純なエージェントメモリは、多くの場合、次の弱い形式に落ちる。

1. 追記型チャットログ
2. ベクトル検索ストア
3. モデルが勝手に書く非構造メモ

これらは有用だが、不十分である。

Layer-0再合成メモリアーキテクチャでは、次を分離する。

- 生イベントの出典
- 要約生成
- 保持ポリシー
- ライフサイクル状態
- 更新／置換
- コンテキスト生成
- 監査出力

この分離により、メモリは次の性質を持てる。

- モデル交換可能
- 検査可能
- 取り消し可能
- コンテキスト予算を意識可能
- 古い情報や一時情報に強い
- 長期セッションをまたいで利用可能

## 6. 決定論ポリシー

このリポジトリの中核成果物は、実行可能で再現可能である。  
そのため、このデモはリモートLLMを呼ばない。

`LEARNED_PARAMETERIZED_TRANSFORM` 役割は、ネットワークアクセス、APIキー、非決定論的サンプリング、ベンダー固有挙動なしにライフサイクルを監査できるよう、決定論的スタブで表現している。

実運用では、このスタブを次のものに置換できる。

- フロンティアLLM
- ローカルLLM
- 小型要約モデル
- ルール + モデルのハイブリッド抽出器

周辺のメモリ制御構造は同じまま残る。

## 8. 研究上の含意

Layer-0定理は、LLM該当性の境界定理であるだけではない。  
それは同時に、再合成可能な設計空間を開く。

モデルクラスを機能役割へ分解できれば、その役割は次のように扱える。

- 削除する
- 置換する
- 外部化する
- 制約する
- 決定論化する
- ポリシーレイヤーに通す
- 状態機械操作へ変換する

これによりLayer-0は、分類結果から **アーキテクチャ探索の基盤** へ拡張される。
