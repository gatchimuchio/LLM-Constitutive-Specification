# Layer-0 言語関係境界 — 2026-08-25

## 状態

`WORKING / NOT_CANONICAL / REOPENABLE`

目的は、`target_relations`のうち何をLanguage Modelの対象relationと呼ぶかを詰め、言語I/Oを使うだけの非LM systemとの境界を明確化することである。

---

# 1. 言語状態

言語状態とは、宣言されたlanguage scope内の差異へ接続された状態である。

少なくとも次のいずれかへ追跡できる。

- 言語記号・単位
- 順序・系列
- 構造
- 文法的役割
- 語彙関係
- 意味関係
- 談話・参照関係
- 言語候補・その評価

内部表現はvector、ID、graph等でよい。

内部表現それ自体をlanguageと呼ぶ必要はない。

---

# 2. 言語関係の三分類

## 2.1 内在言語関係

一つのlanguage scopeまたはその内部構造の中で成立するrelation。

例:

- token/word候補評価
- sequence relation
- masked reconstruction
- syntax/grammar relation
- contextual representation relation
- discourse/coreference relation
- semantic relation expressed within language states

**Language Model Coreの主対象候補はここ。**

## 2.2 言語間関係

複数language scope間のrelation。

例:

- translation
- transliteration
- cross-lingual alignment

これは`Cross-Language Model`として独立分類できる。

内部に内在言語relationを持つ場合、そのsubmodelはLanguage Modelとして別監査する。

## 2.3 言語外関係

言語状態と非言語対象とのrelation。

例:

- image→caption
- audio→transcript
- text→sentiment label
- text→arithmetic value
- question→world fact

これらは言語を含んでも、relationの主対象がlanguage internal relationとは限らない。

---

# 3. Language Model Coreの境界候補

> **Language Model Coreは、少なくとも一つの内在言語関係を対象Tとして持ち、その有限モデル射影Mが当該relationへ適合することを要求する。**

これにより、

- unigram
- n-gram
- grammar model
- contextual encoder
- autoregressive LM
- diffusion LM

を同じ根へ置ける。

一方、

- pure calculator
- pure sentiment head
- pure image→caption lookup
- pure QA lookup

をlanguage I/OだけでLMへ昇格させない。

---

# 4. 「意味関係」の扱い

意味をすべてworld relationへ追い出すと、現代LMの重要なlanguage semanticsを失う。

逆に、world factをすべてlanguage semanticsへ入れると境界が消える。

従って次を分ける。

## linguistic semantic relation

言語表現間の意味対応・言い換え・含意・指示・役割等。

## world knowledge relation

言語表現が指す外界・事実・時点等のrelation。

両者は接続し得るが同一ではない。

Language Model identityはworld knowledgeの保存量を必須としない。

---

# 5. 表現名の不変性

内部token ID、node ID、vector coordinate等の名称は本質ではない。

一貫した再符号化を行って同じrelationが保たれるなら、model identityは保たれ得る。

従って、

```text
surface label identity
!=
language relation identity
```

とする。

これはtokenizer implementationをLayer-0の本質へ昇格しない根拠になる。

---

# 6. negative controlを固定しない

前段草案のC4で、`global prior`を普遍null候補に含めたのは強すぎる。

unigram LMではglobal prior自体が正当なtarget relationになり得る。

従ってC4を次へ修正する。

> **C4 — 対象Tに対して、relationを一段単純化・破壊・無関係化した適切なcountermodelと区別できること。**

例:

## unigram

- uniform/random token score

## n-gram

- lower-order model
- shuffled context relation

## grammar model

- shuffled grammar rules
- structure-insensitive baseline

## contextual encoder

- context-fixed / context-shuffled baseline

## diffusion LM

- denoising relation破壊

## MINIDORA将来監査

- language relationを落としてworld/task relationだけ残したsystem

対象に合わない固定controlを普遍化しない。

---

# 7. exact retrieval再監査

`exact retrieval`という実装名だけでは判定できない。

## 非LM寄り

```text
instance_id -> stored complete answer
```

主relationが個体同一性・world knowledge retrieval。

## LM候補

```text
linguistic context -> linguistic candidate score
```

をtable lookupで実装するn-gram等。

従って、何をlookupするかではなく、**Tのrelation kind**を見る。

---

# 8. code / formal language

任意bit列をlanguageへ無限定化しない。

候補systemは、

- external sign system
- composition/order rules
- declared language scope
- modeled internal relations

を示す。

codeやformal languageはこの契約を満たし得る。

内部machine codeやopaque tensor coordinateを自動的にlanguageとはしない。

---

# 9. multimodal境界

## pure mapping

```text
image -> text
```

だけではLM Coreとは限らない。

## LM subrelationあり

```text
image_state
+
prior_language_state
-> next/updated language_state
```

等を持つ場合、language subrelationを分離監査する。

multimodal whole-system identityとLanguage Model submodelを混同しない。

---

# 10. 現時点の判定

- LM Coreに少なくとも一つの内在言語関係を要求: **強く支持**
- language I/OだけでLM認定: **否定**
- cross-language / multimodal relationをLM Coreへ自動統合: **否定**
- semantic relationとworld knowledge relationを分離: **支持**
- fixed universal negative control: **不採用**
- target-relative countermodel: **採用方向**
- code/formal languageを原理的に排除: **不採用**

この境界をv5最終候補へ統合する。
