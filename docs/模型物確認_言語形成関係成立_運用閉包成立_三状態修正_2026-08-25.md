# 模型物確認・言語形成関係成立・運用閉包成立 — 三状態修正

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 修正理由

前稿では、

- 構造成立
- 実行成立
- 生成運用成立

を分けた。

しかし「構造成立」という語は、artifactの存在・architecture形状だけで言語模型性が成立したように読める。

同じclass/configを持つrandom weightでも物理構造は作れるため、この表現は過剰である。

従って、状態語をさらに分ける。

---

# 1. 模型物確認

## 1.1 定義候補

> **模型物確認とは、版として同定可能なartifact・規則・表・graph・program等の成立物が存在し、その物理・論理構造を観測できる状態である。**

これは言語模型機能の成立を意味しない。

---

## 1.2 例

- checkpointが存在する
- configが読める
- weight shard hashが固定される
- rule setが存在する
- tableが存在する
- source codeが存在する

これらは模型物確認の証拠。

---

# 2. 言語形成関係成立

## 2.1 定義候補

> **言語形成関係成立とは、模型物または候補系が、宣言した対象言語関係に対応して、文脈付き言語状態から言語形成状態を生じさせる関係を実際に持つことが確認された状態である。**

ここが言語モデル性の中心判定である。

---

## 2.2 必要な証拠

artifactの名称・architectureだけでは足りない。

少なくとも、

- 実行trace
- 再現済み出力relation
- 開発元が固定した実行証拠
- 独立評価

等により、対象言語relationへの対応を確認する。

どの証拠型を要求するかは対象・公開度によって変える。

---

## 2.3 random weight

```text
模型物確認 = 成立
言語形成関係成立 = 不成立 / 未確認
```

と分ける。

これによりarchitecture名から言語model性を自動導出しない。

---

# 3. 運用閉包成立

## 3.1 定義候補

> **運用閉包成立とは、外部言語入力から言語住所接続、模型形成relation、必要な表出作用を経て、外部言語結果まで実際に閉路が成立する状態である。**

```text
外部言語
→ 内部住所
→ 文脈付き内部言語状態
→ 模型形成relation
→ 言語形成状態
→ 表出作用
→ 外部言語結果
```

---

## 3.2 model relationと運用故障

模型物と形成relationが正常でも、runtime / decoder / environment等が壊れていれば運用閉包は成立しない。

この場合、形成relation成立を自動取り消さない。

---

# 4. 閉鎖モデル

closed APIでは、

- 模型物: 未観測
- 内部形成relation構造: 未観測
- 外部機能relation: 観測可能
- 運用閉包: service boundaryで観測可能

となり得る。

この場合、

> **言語形成機能観測**

を別状態として持つ案を残す。

外部機能から内部模型物を推測しない。

---

# 5. 四状態候補

最終的には次の四つを分ける方がよい可能性がある。

1. **模型物確認**
2. **言語形成機能観測**
3. **言語形成関係成立**
4. **運用閉包成立**

### 開放モデル

1〜4を比較的直接監査できる。

### 閉鎖モデル

2・4は観測できても、1・3の内部構造は保留し得る。

---

# 6. 大規模資格

上記四状態とは別に、

- 状態域規模
- 関係域規模
- 共有適用規模

を記録する。

大規模資格を形成relation成立の証拠と混ぜない。

---

# 7. 旧Layer-0への帰還

旧仕様のcandidate-local PASSは、

- artifact
- functional evidence
- result surface

を一つのPASSへ集めやすかった。

新案では、

```text
何が存在するか
何が外から観測できるか
内部に何のrelationが成立するか
end-to-endで動くか
```

を別状態へ分ける。

---

# 8. 現時点の正本候補状態語

- 模型物確認
- 言語形成機能観測
- 言語形成関係成立
- 運用閉包成立
- 大規模資格

各項目について、

- 成立
- 不成立
- 保留
- 未観測
- 対象外

を持つ案。
