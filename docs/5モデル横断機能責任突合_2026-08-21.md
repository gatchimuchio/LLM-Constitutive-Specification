# 5モデル横断機能責任突合 — 2026-08-21

## 1. 目的

Layer-0 v4の5責任が、特定のTransformer実装・Attention方式・FFN方式・入力媒体へ過剰適合していないかを、異なる公開モデル系統のHDS日本語構文化資料から再監査する。

この文書は、新しい最小構成を先に決めるものではない。

確認するのは次である。

> 実装機構を横へ引いたとき、現行5責任が異種family間でも維持できるか。

### 観測深度の非対称

K3はweight shardとtensorまで実読されている一方、他4系統は主として公開資料・実装・形成履歴の意味構文化である。

したがって、K3だけ局所機構が細かく見えることを「K3だけ責任が多い」根拠にしない。

## 3. 分析独立性の境界

4つの日本語構文化は、K3で用いた「教師固定→HDS意味分別→残差保持」の前半方式を継承している。

よって、同じ語彙・同じ記述形式へ整ったこと自体は独立検証ではない。

今回の証拠価値は次に置く。

> Dense / MoE、standard attention / KDA、KV系 / recurrent state、text-only / multimodalという実物側の差を保持したまま、上位機能責任への写像が維持できるか。

## 4. 現行5責任への横断写像

### 4.1 `LINGUISTIC_ADDRESSABILITY` — 言語アドレス化

| 対象 | 観測された接続 |
|---|---|
| Llama 3 | 文字列 → tiktoken/BPE + 特殊token → token ID列 → embedding |
| K2-V2 | Jais250k系 tokenizer → token IDs → dense transformer |
| OLMo 3 | Dolma2 tokenizer → padded vocab → model embedding/head |
| Apertus 1.5 | base text ID維持 + OMNI reserved / modal codebook → shared model sequence |
| Kimi K3 | `tiktoken.model`によるtoken住所化。processor / encodingがtext・role・tool・vision入力をモデル入力関係へ接続 |

個別tokenizer名・語彙数・媒体表現は異なるが、**外部記号を内部で参照可能な住所へ接続する責任**は共通して残る。

### 4.2 `CONTEXT_BOUND_STATE` — 文脈束縛状態

| 対象 | 観測された状態保持・文脈利用 |
|---|---|
| Llama 3 | causal系列 + KV cache。既出位置を保持し新規位置を追加 |
| K2-V2 | 8K→32K→64K→128K→512Kの段階形成。論理長系列をContext Parallelで物理分割 |
| OLMo 3 | 8K→65K、YaRN、長文書mix、Context Parallel。論理系列と物理分割を分離 |
| Apertus 1.5 | continued trainingにより262Kへ拡張。modal tokenもshared sequenceへ接続 |
| Kimi K3 | KDAのchannel-wise decay / write strength / recurrent state + 周期的Gated MLA。最大1M token context |

KV cache、位置尺度、Context Parallel、KDA recurrent stateは同一機構ではない。残るのは**現在処理を過去・周辺の有効状態へ束縛する責任**である。

### 4.3 `TRANSFORMATION_OR_COMPOSITION_CORE` — 変換・合成中核

| 対象 | 観測された変換・合成 |
|---|---|
| Llama 3 | Q/K/V attention + FFN + residual差分累積 |
| K2-V2 | dense Transformer backbone、GQA、FFN |
| OLMo 3 | 規模別attention形状を持つTransformer、dense系変換 |
| Apertus 1.5 | decoder-only / xIELU backboneを維持しつつ媒体・context契約を拡張 |
| Kimi K3 | KDA + Gated MLA + Attention Residuals + Stable LatentMoE |

ここから直接言えるのは、**特定の変換機構名が普遍必須ではなく、状態に関係作用を与えて次状態へ変換・合成する責任が再現する**ことまでである。

K3もGated MLAを含むため、「Attention一般が不要」とは判定しない。

### 4.4 `CONTEXT_DEPENDENT_RESULT_FORMATION` — 文脈依存結果形成

| 対象 | 観測された結果形成 |
|---|---|
| Llama 3 | logits → decoding → 次token。生成可能性と最終選択、temperature/top-p/argmaxを分別 |
| K2-V2 | same weights + effort special tokenによりgeneration length / behaviorが変化 |
| OLMo 3 | BaseからThink / Instructへ別形成経路。形成済みparameterをinferenceで使用 |
| Apertus 1.5 | same model + thinking control、tool protocolにより生成挙動が変化 |
| Kimi K3 | role / content / thinking / toolのencodingと内部状態変換が言語出力形成へ接続 |

共通して、**内部に生成可能な状態があること**と**そこから何を選択・表出するか**を完全同一視できない。

### 4.5 `RESULT_SURFACE` — 結果表面

5系統はいずれも最終的に言語結果を外部へ表出する。

Apertus 1.5とKimi K3は入力側にmultimodal経路を持つが、これはtext-onlyモデルにも存在しなければならない責任ではない。Layer-0で残るのは、**形成済み結果をsystem boundary外から観測可能にする責任**である。

## 5. 横へ引けた実装要素

今回の観測集合では、次をLayer-0の固有機構へ固定する根拠は成立しない。

| 実装要素 | 横断観測 |
|---|---|
| Dense FFN | K3はMoEを使用するため普遍実装ではない |
| MoE | Llama 3 / K2-V2 / OLMo 3等がDense系で成立するため普遍実装ではない |
| 全層standard full-attention | K3はKDA主体 + 周期的Gated MLAで成立するため普遍配置ではない |
| 特定のKV共有方式 | GQA / MLA / KDA等が分岐する |
| 特定のlong-context手段 | RoPE尺度遷移、YaRN、continued training、KDA等へ分岐する |
| multimodal入力 | text-onlyモデルが成立するため必須ではない |
| thinking / effort control | base modelと制御付きmodelが分離して存在するため必須ではない |
| tool protocol | tool useなしのLLMが成立するため必須ではない |
| 特定post-training recipe | PPO / DPO / SFT / RLVR等が版・familyで変化する |
| training物理構成 | runtime Functional Coreとは分離して記録可能 |

### Attentionについての境界

K3はKDA主体であるが、周期的Gated MLAを保持する。

よって今回の集合から確定できるのは、**標準full-attentionを全層に同一方式で配置することは普遍必須ではない**という範囲である。

「Attentionという抽象一般が不要」までは、この5資料だけでは確定しない。

## 6. 7局所作用と5責任

横断すると、実装内の局所作用は次の7つへ細分できる。

1. 外部記号の住所化
2. 履歴・系列状態の保持
3. 参照関係の形成
4. 状態変換
5. 差分・参照結果の統合帰還
6. 候補の表出
7. 選択・反復

しかし、これらは現行5責任へ次のように写像できる。

```text
住所化                  -> LINGUISTIC_ADDRESSABILITY
履歴保持                -> CONTEXT_BOUND_STATE
参照関係形成            -> TRANSFORMATION_OR_COMPOSITION_CORE
状態変換                -> TRANSFORMATION_OR_COMPOSITION_CORE
統合帰還                -> TRANSFORMATION_OR_COMPOSITION_CORE / RESULT_FORMATION
候補表出                -> CONTEXT_DEPENDENT_RESULT_FORMATION
選択・反復              -> CONTEXT_DEPENDENT_RESULT_FORMATION / RESULT_SURFACE
```

したがって、今回の証拠だけで責任数を5から7へ増やすのは過分解である。

## 7. Claim layer更新

今回の結果を次のように反映する。

| 層 | 更新後 |
|---|---|
| L0-A | 変更なし。candidate-local evaluatorが直接判定 |
| L0-B | 観測済みfamily内で支持 |
| L0-C | **Llama 3 / K2-V2 / OLMo 3 / Apertus 1.5 / Kimi K3 の観測集合で支持** |
| L0-D | `PRINCIPLE_CANDIDATE / REOPEN_REQUIRED` を維持 |
| L0-E | OPEN |

L0-Cの意味は「同じ機構が再現」ではなく、**異なる機構を越えて同じ機能責任が再現**である。

## 8. 非主張

今回の突合から次は主張しない。

- 5責任が普遍的一意最小である。
- 5責任が最終形である。
- 全LLM familyを観測した。
- standard attention一般が不要である。
- neural network一般が不要である。
- candidate-local適合が通常語義のLLMと自動的に同値である。
- K3のweight-level観測深度と他4系統の資料観測深度が同一である。

## 9. 再開放条件

次のいずれかが得られた場合、この横断結論を再監査する。

1. 現行5責任の一つを欠いたまま同等の言語機能を成立させる実装。
2. 現行5責任へ写像できない独立必須作用。
3. 5責任のうち複数を、機能差を失わず恒常的に一責任へ統合できる観測。
4. source artifactの版境界・hash・教師固定・HDS残差に破損が見つかった場合。
5. 未観測familyで現在の責任語彙が説明力を失う場合。

## 10. 結論

現時点で最も説明力が高い読みは次である。

> LLMのLayer-0をTransformer、Attention、MoE等の部品名で固定するより、言語アドレス化・文脈束縛状態・変換/合成・文脈依存結果形成・結果表面という機能責任で記述した方が、観測した異種architectureを一貫して扱える。

この結論は観測5系統に対するL0-C支持であり、普遍定理または最終最小性の宣言ではない。
