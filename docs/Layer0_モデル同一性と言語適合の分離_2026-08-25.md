# Layer-0 モデル同一性と言語適合の分離 — 2026-08-25

## 状態

`WORKING / NOT_CANONICAL / REOPENABLE`

M1「言語状態域契約」+ M2「再利用可能なモデル関係」だけでは、任意のrandom mappingやhash-like transducerまで形式上は通り得る。

この問題を、`learned`や`parameterized`をCoreへ戻すことで解決してはならない。

---

# 1. 三つを分ける

## I. 構造同一性

何であるか。

```text
M1 言語状態域契約
M2 再利用可能なモデル関係
```

## C. 言語モデル適合

そのmodel relationが、実際に言語状態間の規則性・条件依存性・構造を保持し、複数状態へ適用できるか。

## L. Large

その適合がどれだけ広い状態域・関係域・再利用域へ及ぶか。

---

# 2. なぜConstructionをCoreへ戻さないか

言語規則性を持つmodel relationは、

- corpusから学習
- 人手規則
- compiler
- program synthesis
- search
- hybrid

等で形成できる。

従って、

```text
trained = LM
not trained = not LM
```

とはしない。

必要なのは形成方法ではなく、形成後のrelationが言語状態域で何を成立させるかである。

---

# 3. 言語モデル適合の最小観測候補

固定の単一benchmarkを普遍化しない。

対象modelの宣言scopeに応じ、少なくとも次を確認する。

## C1. 言語差依存

言語状態の意味ある差異を変えたとき、model relationの結果・評価が無関係な定数のままではない。

例:

- context差
- 語順差
- token差
- 構造差
- mask位置差
- 関係差

対象modelが扱うと宣言した差異だけを要求する。

## C2. 規則性保持

結果が任意乱数・hash的対応ではなく、宣言scopeの言語関係について反復可能な規則性を示す。

検証形式はmodel classごとに異なってよい。

- predictive accuracy
- reconstruction
- conditional ranking
- grammatical acceptance
- semantic relation consistency
- structural transformation consistency

等。

## C3. relation再利用

一つの完全入力→完全出力pair専用ではなく、複数の状態へ同じmodel relationが適用される。

## C4. nullとの差

必要に応じて、

- constant output
- random mapping
- global prior
- identity mapping
- exact instance retrieval

等の適切なnull/controlと比較し、宣言した言語関係をmodel relationが実際に担うことを確認する。

これは常に統計検定を要求するという意味ではない。対象に応じた反例・実行trace・構造観測でよい。

---

# 4. random weight artifactの扱い

random initializationされたTransformer等は、

- M1/M2の構造同一性を持ち得る
- しかしC1-C4の言語適合は満たさない可能性が高い

従って、

```text
LM_ARTIFACT_STRUCTURE = PASS
LM_FUNCTIONAL_CONFORMANCE = FAIL / SUSPEND
```

と分けられる。

これにより「model architecture」と「機能するlanguage model」を同一視しない。

---

# 5. exact retrievalの扱い

exact retrievalはM1/M2を形式上満たすことがある。

しかし、完成個体identityの取得しか行わず、宣言scopeで新しいrelation evaluationを形成しない場合、C3/C4で縮退する。

一方、conditional tableによるn-gram評価は、table lookupを使っていても複数context/candidateへ同一relationを適用するためC3を満たし得る。

従って保存方式の名称ではなく、**relationの作用**で分ける。

---

# 6. parser / grammarの扱い

grammar relationを複数入力へ再利用し、構造差を一貫して形成するならC1-C3を満たし得る。

従ってLanguage Modelの構造・機能候補から名称だけで排除しない。

Large profileの関係域幅・再利用域幅で現代frontier LLMとの差を保持する。

---

# 7. classifierの扱い

classifier systemは言語encoderを内包し得る。

- encoder relation: LM conformance候補
- task head: application relation

として分離する。

固定labelだけを返すtask headを、言語モデル適合の証拠にはしない。

---

# 8. 新しい適合状態候補

## Model Artifact Identity

- `PASS_MODEL_ARTIFACT`
- `FAIL_MODEL_ARTIFACT`
- `SUSPEND_MODEL_ARTIFACT`

## Language Modeling Conformance

- `PASS_LM_FUNCTION`
- `FAIL_LM_FUNCTION`
- `SUSPEND_LM_FUNCTION`

## Large Profile

二値PASSを普遍化せず、L1-L3 profileを返す。

用途別reference envelopeがある場合だけ、

- `WITHIN_REFERENCE_LARGE_ENVELOPE`
- `BELOW_REFERENCE_LARGE_ENVELOPE`

等を付せる。

---

# 9. 現時点の判定

- M1/M2だけでfunctional LMを断定: **不十分**
- learned/parameterizedをCoreへ戻す: **否定**
- 構造同一性と言語適合を分ける: **強く支持**
- random/hash controlを入れる: **必要**
- exact retrievalをstorage方式だけで排除: **否定**
- Largeをfunctional conformanceと混ぜる: **否定**

この分離により、Layer-0は「何であるか」「本当に言語をmodelしているか」「どれだけ広いか」を別々に監査できる。
