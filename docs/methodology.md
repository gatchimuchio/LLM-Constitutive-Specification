# Methodology — v4

1. Declare candidate and system boundary.
2. Separate Functional Core from construction/provenance and operational wrapper.
3. Map responsibilities to mechanisms without assuming one-to-one component identity.
4. Require execution evidence for every required responsibility.
5. Run mandatory negative controls.
6. Return `PASS / FAIL / SUSPEND / NOT_APPLICABLE`.
7. Keep family recurrence and broader principles in separate claim layers.
8. Reopen claims when counterexamples or new mechanisms appear.

The v3 declared-obligation graph remains a legacy internal certificate, not the v4 proof method.
