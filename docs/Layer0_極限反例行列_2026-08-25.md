# 1. 監査する核候補

現時点の最小候補を次の一関係として置く。

> **Language Model Core = 言語状態域に存在する言語上の規則的関係を、複数の状態へ再利用可能なモデル関係として保持するもの。**

監査上は三面へ分ける。

1. **状態域** — 何についてのmodelか
2. **モデル関係** — 何を再利用するmodelか
3. **言語適合** — そのrelationが実際に言語規則性を担うか

三面は三physical componentsを意味しない。

---

# 2. 言語規則性の暫定意味

ここで「言語規則性」は、自然言語学の特定理論へ固定しない。

少なくとも、宣言scope内で、言語状態の差異・組合せ・関係を変えたとき、その差に応じて反復可能なrelation差が生じることをいう。

例:

- 次状態候補の適合差
- mask復元差
- 文脈化表現差
- 構造関係差
- 文法適合差
- 翻訳対応差
- 意味関係差

単なるinstance ID照合、乱数、hash、定数出力をこれだけで言語規則性とはしない。

# 4. 重要な帰結

## 4.1 「言語を入力する」では足りない

calculator、classifier、image caption lookupが反例。

主model relationが**言語状態間の規則性**を担う必要がある。

## 4.2 「言語を出力する」でも足りない

image→caption lookup、検索engineが反例。

言語はsurfaceではなくmodel relationの対象域でなければならない。

## 4.3 「table/ruleだから非LM」は成立しない

unigram、n-gram、grammar、phrase modelが反例。

storage/implementation方式ではなく、何のrelationをmodelしているかを見る。

## 4.4 「context必須」はLM一般では成立しない

unigram反例。

ただし現代Large Language Model参照群では、context relationは非常に強い共通特徴として別profileへ置ける。

## 4.5 「生成必須」はLM一般では成立しない

contextual encoder反例。

Generativeは別属性。

## 4.6 「学習済み必須」は成立しない

grammar / authored / compiled relationの可能性を定義だけで排除しない。

実際に言語規則性を担うかをFunctional Conformanceで判定する。

# 5. マルチモーダル境界

HDS横断観測では、Apertus 1.5は中央decoderを維持したままvision/audio前段を追加し、Gemini系では内部integration topologyが未観測である。

従って、

```text
multimodal model
=
必ずしも whole model が Language Model という意味ではない
```

とする。

監査は、

1. language-conditioned state pathが存在するか
2. language relationを担うmodel relationがあるか
3. multimodal front-end / adapterとのboundaryはどこか

を分ける。

出力がtextであることだけをLM証拠にしない。

---

# 6. 「言語」のscope

自然言語だけへ限定するとcode-oriented LMを不自然に排除する。

一方、任意bit列まで無限定にlanguageと呼ぶと境界が消える。

従って候補systemは、少なくとも次を宣言する。

```text
language_scope
external_sign_system
state_mapping
modeled_relations
```

`language_scope`は、自然言語、人工言語、形式言語、code等を含み得る。

内部token IDやvector座標そのものをlanguageと呼ぶ必要はない。外部language scopeとのmappingを追跡する。
