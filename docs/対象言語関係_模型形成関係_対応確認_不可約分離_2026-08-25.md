# 対象言語関係・模型形成関係・対応確認 — 不可約分離

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 修正理由

大規模言語モデルの中核を、

```text
文脈付き言語状態
→ 言語形成可能域
```

という一関係まで圧縮する案が出た。

しかし、入出力の型だけなら、

- random mapping
- hash
- arbitrary table
- 固定擬似score生成器

でも満たせる。

従って、

> **何の言語relationを対象にしているか**

と、

> **モデルが実際に何のrelationを形成するか**

と、

> **両者が対応していると何によって確認するか**

を分ける必要がある。

---

# 1. 対象言語関係

## 1.1 定義候補

> **対象言語関係とは、本版で対象化した自然言語状態の間に、形成対象として切り出した関係である。**

例:

- 文脈と継続状態の関係
- 文脈と欠損復元状態の関係
- 入力表現と意味を保持した変換先表現の関係
- 周辺状態と候補言語状態の適合関係

この一覧を普遍最終集合へしない。

---

## 1.2 対象言語関係は自然言語そのものではない

対象言語関係も有限Projectionである。

```text
自然言語そのもの
≠
本版で切り出した対象言語関係
```

を維持する。

例えば「次token」という関係はLlama系の形成方式を記述するには有効だが、自然言語全体の唯一の関係ではない。

---

# 2. 模型形成関係

## 2.1 定義候補

> **模型形成関係とは、モデルartifactが内部状態上で再利用し、現在の文脈付き状態から形成可能域を生じさせる関係である。**

内部実装は問わない。

- neural weight
- rule
- recurrence
- attention
- table
- graph
- hybrid

等を許容する。

---

## 2.2 模型形成関係は対象言語関係そのものではない

```text
対象言語関係
≠
模型形成関係
```

モデルは対象を有限に写した成立物であり、対象そのものではない。

この非同一を正本境界へ置く。

---

# 3. 言語住所対応

対象言語状態と模型内部状態を比較するには、対応関係が必要になる。

> **言語住所対応とは、外部自然言語状態と、モデル内部で参照される位置・記号・状態との対応を示す関係である。**

これにより、模型形成関係が何の外部言語relationに接続しているかを追跡する。

tokenizer等はこの対応の実装例であり、名称を普遍必須にしない。

---

# 4. 対応確認

## 4.1 定義候補

> **対応確認とは、模型形成関係による状態差が、宣言した対象言語関係の差と対応していることを、観測範囲内で確認することである。**

これを、artifactの存在や名称から自動推定しない。

---

## 4.2 random mappingが落ちる理由

random mappingでも、

```text
入力状態
→ score列
```

は生成できる。

しかし、そのscore差が対象自然言語の文脈・継続・復元等のrelationと対応しなければ、対応確認が成立しない。

従って大規模言語モデル成立へ昇格しない。

---

# 5. 対応確認で固定しないもの

対応確認を、

- 特定benchmark
- cross entropy
- perplexity
- 人手評価
- next-token accuracy

のどれか一つへ固定しない。

対象言語関係に応じて、確認方法は異なり得る。

ただし、確認方法・条件・対象範囲・失敗条件を明示する。

---

# 6. 現代運用型LLMの中核候補

原対象群については、対象言語関係の中心を暫定的に、

> **文脈付き自然言語状態と、未提示言語状態の形成可能性との関係**

として切り出せる。

模型側は、

> **文脈付き内部言語状態から、言語形成可能域を形成する関係**

を持つ。

そして対応確認により、両者の差が対応していることを確かめる。

---

# 7. 三者の最小閉包

```text
対象自然言語
  │
  ├─ 対象言語関係
  │
  │  言語住所対応
  ▼
モデル内部状態
  │
  ├─ 模型形成関係
  ▼
言語形成可能域

対象言語関係
      ↕ 対応確認
模型形成関係
```

これを物理component図として読まない。

必要な**意味区別**である。

---

# 8. 対象域・形成関係・規定境界との関係

前段の三位閉包候補へ戻すと、

### 対象域

- 自然言語状態
- 対象言語関係

### 形成関係

- 模型形成関係
- 形成可能域

### 規定境界

- 言語住所対応
- 対応確認
- 同一性
- 大規模性
- 版
- 外周分離
- 採否

と整理できる。

従って、T/M/C型の区別を英語略号ごと捨てる必要はなかった。

**英語骨格を捨て、日本語で不可約な意味差だけを残す。**

---

# 9. 現在の最短定義候補の修正

旧候補:

> 大規模言語モデルとは、定めた自然言語対象域について、文脈に応じた未提示言語状態の形成関係を大規模に保持・適用する有限モデルである。

修正候補:

> **大規模言語モデルとは、定めた自然言語対象域について、文脈と未提示言語状態の対象関係に対応する形成関係を、大規模な状態・関係範囲で保持・適用するモデルである。**

これにより「対応」を定義へ戻し、random mappingを排除する。
