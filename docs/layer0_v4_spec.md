# Layer-0 v4 Provisional Specification

## Purpose

Evaluate whether a candidate processes linguistic requests under context and forms results through traceable transformation or composition without binding conformance to a particular implementation method.

Status: `PRINCIPLE_CANDIDATE / REOPEN_REQUIRED`

## Functional Core

- `LINGUISTIC_ADDRESSABILITY`
- `CONTEXT_BOUND_STATE`
- `TRANSFORMATION_OR_COMPOSITION_CORE`
- `CONTEXT_DEPENDENT_RESULT_FORMATION`
- `RESULT_SURFACE`

These are responsibility boundaries, not a claim about physical component count.

## Construction / Provenance

`trained / authored / compiled / induced / searched / evolved / retrieved / hybrid / unknown`

Construction profile is separated from functional PASS/FAIL.

## Operational Wrapper

`token_emission / text_api / score_surface / structured_output / interactive_chat / batch_transform / embedded_subsystem / unknown`

## Candidate schema

A candidate records at least:

```text
candidate_id
candidate_version
system_boundary
functional_evidence
mechanisms
construction_profile
operational_profile
source_material_digest
execution_trace
negative_controls
unknowns
scope
reopen_conditions
```

## Status

- `PASS`: all required responsibilities and negative controls are established
- `FAIL`: a required responsibility or negative control is falsified
- `SUSPEND`: evidence, trace, source, or boundary is insufficient
- `NOT_APPLICABLE`: outside scope

## Claim boundary

v4 directly evaluates candidate-local conformance. Family recurrence, cross-family recurrence, scoped principles, and transfer are separate claim layers.

Current open states:

```text
exact minimum                  = OPEN
ordinary-term LLM equivalence = OPEN
universal theorem             = NOT CLAIMED
```
