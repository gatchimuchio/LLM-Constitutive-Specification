# 旧Layer-0六構成 — 帰属階層の再配置

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 結論

旧Layer-0の六構成で観測していた事象を全て誤りとして捨てる必要はない。

主要な誤りは、

> **異なる階層に属するものを、LLM成立の同格な最小構成として横並びにしたこと**

である可能性が高い。

---

## 1. 旧六構成

旧系統では、概ね次をLayer-0へ置いていた。

1. 記号・token空間
2. 文脈条件状態
3. 学習済み・parameterized変換
4. 条件付き言語出力面
5. 系列学習基準または同等形成基準
6. 復号・表出interface

この六つを新しい日本語基底の成立階層へ再配置する。

---

## 2. 記号・token空間

### 旧位置

LLM中核構成。

### 新位置候補

> **言語住所規約 / 言語接続同一性**

自然言語の文字・語・部分語等を、モデル内部で参照可能な位置へ対応づける規約。

### なぜ単なるwrapperではないか

学習済みweightがtoken IDへ結びついているモデルでは、token IDと文字列の対応を無関係な別対応へ交換すると、同じweightでも元の言語relationを保てない。

従って、

- tokenizer
- vocabulary
- special token mapping
- role marker mapping
- byte/character encoding

等は、物理配置にかかわらず**モデルがどの言語状態を何として参照するかという同一性境界**へ寄与し得る。

### ただし

特定tokenizer方式を必須にしない。

文字直結、byte直結、構造記号、別のsymbol addressingでもよい。

---

## 3. 文脈条件状態

### 旧位置

独立Layer-0構成。

### 新位置候補

> **中核関係の条件側**

現代運用型LLM群では、現在の言語状態だけでなく、既出・周辺・条件状態の差が形成可能域へ作用する。

文脈を、独立した物理componentとして要求する必要はない。

- KV cache
- recurrent state
- sliding window
- compressed memory
- full attention
- input refeed

等は文脈依存を実現する個別方式である。

### 現在の意味

文脈依存は原対象7系統で反例がなく、**広域文脈依存言語形成**の不可欠な条件面として残る。

---

## 4. 学習済み・parameterized変換

### 旧位置

LLM存在条件。

### 新位置候補

二つに分離する。

#### A. 変換・状態作用

モデルが現在状態へ何らかのrelationを適用すること自体は中核実行に必要。

ただし、

- Attention
- FFN
- MoE
- recurrence
- table
- rule
- graph operation

等の特定方式は個別実装である。

#### B. 学習済み / parameterized

これは**形成過程・成立物形式**である。

学習済みであること自体をruntime中核へ置かない。

### 現在の意味

旧構成のうち「変換する」という観測は残る。

「学習済み高容量parameterでなければならない」という主張は撤回候補。

---

## 5. 条件付き言語出力面

### 旧位置

独立Layer-0構成。

### 新位置候補

> **文脈依存言語形成の結果側**

ただし「外部文字列surface」ではなく、まずモデル中核が形成する**言語形成可能域**として読む。

例:

- vocabulary score
- candidate ordering
- token proposal
- denoised token state
- structured candidate state
- deterministic next-state

確率分布である必要はない。

### 重要

モデル中核が形成可能域を作ることと、最終的に一つの外部言語結果を選ぶことを分ける。

---

## 6. 系列学習基準・形成基準

### 旧位置

LLM存在条件。

### 新位置候補

> **形成過程**

pretraining objective、masked objective、next-token、preference、RL、蒸留、コンパイル、手書き等は「そのモデルがどう形成されたか」を記録する。

形成後のruntimeで何を成立させるかとは分離する。

### 現在の意味

形成履歴は能力・構造・同一性の説明に重要だが、**大規模言語モデル成立核そのものではない**。

---

## 7. 復号・表出interface

### 旧位置

Layer-0存在条件。

### 新位置候補

> **運用表出規則 / 結果接続**

モデル中核が形成した言語形成可能域から、外部で観測可能な言語結果へ接続する。

### 重要な分離

Llama 3のHDS構文化でも、同じ学習済みparameterと文脈から、

- argmax
- temperature
- top-p

等によって単発出力が変わることが観測されている。

従って、

> モデルの言語形成可能域

と、

> 単発の表出結果

を同一視しない。

### モデル同一性との関係

通常のsampling設定変更だけでモデル本体の同一性が変わるとは扱わない。

ただし、選択規則がmodel artifactへ不可分に埋め込まれている場合は境界を再監査する。

---

## 8. 新しい階層図

```text
【言語同一性境界】
自然言語
  ↓
言語住所規約
  ↓
内部言語状態

【モデル成立核】
広域な内部言語状態
＋ 文脈
  ↓
同一モデルrelation
  ↓
言語形成可能域

【運用表出】
言語形成可能域
  ↓
選択・復号・表出規則
  ↓
外部言語結果
```

別系統:

```text
【形成過程】
学習 / 後学習 / 蒸留 / 手書き / コンパイル / 探索 ...
        ↓
     model artifact
```

さらに外側:

```text
【利用系】
search / tool / safety / agent / UI / scheduler ...
```

---

## 9. 旧観測の扱い

旧Layer-0で観測したものを削除しない。

次のように変更履歴として保持する。

| 旧観測 | 新帰属候補 |
|---|---|
| 記号・token空間 | 言語住所規約 / 言語同一性境界 |
| 文脈条件状態 | モデル成立核の条件面 |
| 変換 | 個別作用 / model relation実装 |
| learned / parameterized | 形成過程・artifact形式 |
| 条件付き言語出力 | 言語形成可能域 |
| fitting criterion | 形成過程 |
| decoding / emission | 運用表出規則 |

旧観測を「誤りだったから削除」と処理しない。

**観測は残し、帰属階層を訂正する。**

---

## 10. 現在の重要帰結

旧6構成の再配置によって、新しい最小成立構造は、部品一覧ではなく、

> **言語住所規約を通じて自然言語状態へ接続されたモデルが、広い言語状態と文脈に対して同一relationを再利用し、言語形成可能域を形成する**

という関係へ収束する。

運用型生成系としては、さらに表出規則が接続される。

この構造を次巡で最小性監査する。
