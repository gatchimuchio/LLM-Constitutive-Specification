# Layer-0 境界反例監査 — 2026-08-25

## 状態

`WORKING / NOT_CANONICAL`

目的は、暫定4責任を隣接系へ当て、LLMの機能核・境界・作用を過不足なく削ることである。

---

## 1. BERT / encoder-only系

BERTは外部へ自由生成文を出さなくても、左右文脈を同時に条件とし、入力tokenごとの文脈化表現を形成する。

この反例から、次を分離する。

- 外部文字列生成はmodel core必須ではない。
- API/text decoder/emissionはOperational Wrapperへ置ける。
- model coreが形成すべきものは、外部表面そのものではなく**言語へ接続された結果状態**でよい。

従って暫定責任D「言語結果形成」は、独立責任ではなくC「文脈依存モデル作用」の出力側へ統合できる可能性が高い。

### 未確定

現代技術用語としてencoder-only modelをLLMへ含めるかは、この機能監査だけから先に決めない。名称慣習と構造分類を混同しない。

---

## 2. n-gram / unigram

### unigram

- 言語状態: あり
- 文脈状態: なし
- 状態作用: global frequency等による評価・出力形成

従って、文脈有効状態を除去した言語モデルの反例となる。

### n-gram

- 言語状態: あり
- 有限文脈: あり
- 条件付き作用: あり
- 言語結果状態: あり

n-gramは言語モデル核の機能候補をかなり満たす。

ここから「ニューラル」「Transformer」「学習済み高容量parameter」をLM機能核の必要条件にはできない。

一方、それをLarge Language Modelと呼ぶために何が追加で必要かは、**大規模性／言語域条件**へ送る。

旧来の「n-gramだからLLMではない」という名称分類を、新Layer-0の前提にしない。

---

## 3. 記号文法・規則系

文法規則が、

- 言語状態を持ち
- 文脈関係を利用し
- 複数状態へ同じ規則作用を再利用し
- 新しい言語状態・評価を形成する

なら、機能上は言語モデル核へ近づく。

形成方法が人手記述であることを理由に排除しない。

ただし、固定template選択・有限完全列挙・exact lookupしか行わない場合は、**組合せ開放性／適用域**で別分類する。

---

## 4. retrieval-only / retrieval + composition

### exact retrieval only

入力言語は検索keyとして使われるが、取得対象の内部関係をモデル作用で変換・合成しない。

この系は「言語を扱う検索器」として成立しても、言語モデル核の中心例にはしない。

### retrieval + composition

取得状態を現在文脈へ接続し、関係形成・変換・合成・選択を行い、新しい言語接続状態を形成する場合、機能上はmodel core候補となる。

従って「retrievalを使うからLMではない」も採用しない。

---

## 5. diffusion language model

masked diffusion型LMは、左→右next-token逐次生成を使わず、maskされた言語状態を反復的に推定・更新して結果状態を形成する。

従って次は普遍条件ではない。

- autoregressive
- causal left-to-right
- next-token prediction
- KV cache
- sequential decoder

残るのは、言語接続状態・文脈依存・モデル作用・状態更新／結果状態形成である。

---

## 6. classifier / ranker / calculator

### sentiment classifier

言語を入力に使っても、modelの主対象がsentiment labelであり、結果域が固定task labelへ閉じる場合、LLMとの境界は「言語I/Oの有無」だけでは引けない。

### calculator

自然言語parseと自然言語出力を持っていても、主作用は算術状態上の演算であり、言語域への適用はinterfaceとして限定される。

この二例から、LLMを区別するにはFunctional Coreだけでなく、少なくとも次を別に監査する必要がある。

- 言語が単なるinterfaceか、作用対象の主要状態域か
- 結果域が固定task label/templateへ閉じるか
- 未列挙の言語組合せへ同一model作用を再利用できるか
- unrelated domainでcore差替えなしに同じ作用を利用できるか

---

## 7. MINIDORAへの帰還

MINIDORAは重要な境界反例である。

内部Kは自然言語文字列そのものではなく、Compilerが生成したHDS関係・座標・Atomic Fact等を主に扱う。

従って「model core内部が自然言語tokenを直接計算しなければLLMではない」という条件はMINIDORAを定義だけで排除する。

一方、MINIDORA全体では、

```text
自然言語
→ HDS Compiler
→ 言語・意味へ接続された内部状態
→ K / C / Jによる状態作用
→ 言語へ接続可能な結果状態
```

という閉路を持つ。

ここから、Layer-0のmodel boundaryは「tokenを直接処理する単一module」へ固定できない。

重要なのは、内部状態が言語から追跡可能に接続され、model作用後の状態が再び言語へ接続可能であることである。

---

## 8. 暫定4責任の再圧縮

### 旧候補

1. 言語状態接続
2. 文脈有効状態
3. 文脈依存モデル作用
4. 言語結果形成

### 再圧縮候補

#### A. 言語接続状態域

言語差異・言語関係を内部で参照可能な状態域へ接続でき、その状態が処理中も言語との対応を失わないこと。

#### B. 文脈有効関係

複数の言語接続状態の関係・順序・条件・履歴等の差が、後続状態へ作用できること。

#### C. 再利用可能な状態作用

版として同定可能なmodel作用が、現在の言語接続状態と文脈関係へ適用され、状態の参照・評価・関係形成・変換・合成・更新を通じて、新しい言語接続状態またはその評価を形成できること。

このCの出力側に旧D「言語結果形成」を含める。

### 現時点

```text
A 言語接続状態域
+
B 文脈有効関係
+
C 再利用可能な状態作用
```

を**言語モデル核の3責任候補**とする。

まだ正本化しない。

---

## 9. 3責任でも残る問題

3責任だけでは、巨大なn-gram、広域規則系、汎用embedding model等との境界が残る。

これは欠陥というより、`Language Model` と `Large Language Model` の差がFunctional Coreではなく規模・適用域側にある可能性を示す。

したがって次段で、

```text
言語モデル核
×
大規模性／言語域
```

を別軸として監査する。

「Large」をparameter数や学習量へ即座に還元しない。

---

## 10. 現在の主要更新

- 外部結果表面をmodel coreから除外する方向: 強く支持
- autoregressive / next-tokenを普遍条件から除外: 強く支持
- learned/neural/parameterizedを機能核から除外: 強く支持
- 暫定4責任 → 3責任への統合: 有力、未確定
- 言語モデル核とLLM大規模性を二段化: 強く支持、閾値未確定
- exact retrievalとcompositionを分ける: 維持
- MINIDORAをmodule単体ではなく言語閉路を持つsystem boundaryで監査する: 有力

次は「Large」の意味を、容量ではなく適用域・組合せ・関係深度・再利用範囲から監査する。
