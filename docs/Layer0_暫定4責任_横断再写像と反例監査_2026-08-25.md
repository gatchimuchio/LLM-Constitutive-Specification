## 1. 暫定4責任

1. **言語状態接続**
2. **文脈有効状態**
3. **文脈依存モデル作用**
4. **言語結果形成**

これらは物理component数を意味しない。

## 3. 実装機構と暫定4責任を混同しない

### 系列方向

- Llama3: global causal GQA
- OLMo3: sliding ×3 + full ×1
- Qwen3.6: linear/recurrent ×3 + full ×1
- DeepSeek V4: sliding / CSA / HCA
- K3: KDA / MLA

すべて方式は異なるが、文脈状態の差を参照し、次状態へ作用させる点は残る。

### 深さ方向

- standard residual
- AttnRes
- mHC

方式は異なるが、前段状態を後段へ輸送・統合し状態変換を継続する作用が残る。

### 幅方向

- Dense FFN
- MoE
- routed expert + shared expert

hard routingは普遍ではない。従って幅方向の選択はLayer-0必須条件にしない。

## 4. 暫定4責任の除去監査

### 4.1 言語状態接続を除去

残るもの:

- 数値状態
- arbitrary vector state
- generic control state

言語差異と内部状態を結ぶ根拠が消える。

暫定判定: **必要候補**

### 4.2 文脈有効状態を除去

残るもの:

- 固定辞書
- unigram型
- context-free canned response

既出状態・周辺状態の違いが結果へ作用しない。

暫定判定: **必要候補**

### 4.3 文脈依存モデル作用を除去

残るもの:

- opaque storage
- exact whole-record lookup
- 固定反射

状態間の関係形成・変換・更新が成立しない。

暫定判定: **必要候補**

### 4.4 言語結果形成を除去

残るもの:

- latent state processor
- embedding extractor
- internal scorer whose result has no language-addressable result contract

言語モデルとして外へ接続可能な結果状態がない。

暫定判定: **必要候補。ただしencoder-only系の通常語義との境界は再監査対象**

## 5. 4責任だけではLLM十分条件にならない反例

### 自然言語calculator

例:

```text
入力: 「12×8は？」
内部: parse → arithmetic → result
出力: 「96」
```

この系は、

- 言語状態接続: あり
- 文脈有効状態: あり得る
- 文脈依存モデル作用: あり
- 言語結果形成: あり

を満たし得る。

しかし、通常これだけを大規模言語モデルとは呼ばない。

従って、暫定4責任は**言語計算核／言語モデル核の候補**であって、LLM全体の十分条件ではない。

## 6. 「大規模性／言語域」を別軸にする必要

旧v3ではこの差を、

- high-capacity
- learned parameterized transform
- sequence-modeling objective

等へ寄せていた。

今回この方法は採用しない。

理由:

- 実装材料・形成過程を定義へ混入する。
- 非ニューラル／compiled候補を先に排除する。
- parameter数が小さくても広い言語状態域を扱える実装を説明できない。

### 暫定的に観測すべき大規模性／汎用性軸

1. **言語域幅** — 語彙・構文・意味関係のどこまでを同一モデル作用で扱えるか。
2. **組合せ開放性** — 全input-output対を列挙せず、未知組合せへ同一作用を再利用できるか。
3. **領域再利用性** — unrelated domainへ移ってもdomain固有コードへ交換せず同じmodel coreを使えるか。
4. **文脈幅** — 複数状態・長距離関係・階層関係をどこまで保持・利用できるか。
5. **結果域幅** — 固定ラベル／固定templateに閉じず、言語構造として結果を形成できる範囲。
6. **知識依存分離** — 世界知識量とmodel coreの言語計算能力を混同しない。

### 現時点の状態

`OPEN`

これらのどれをLLMの必須大規模性条件にするか、単一thresholdへ潰すか、profileとして保持するかは未確定。

## 7. 境界再定義候補

### 7.1 言語モデル核

暫定4責任を満たす計算核。

### 7.2 大規模言語モデル

```text
言語モデル核
+
大規模性／言語域条件
```

とする候補。

### 7.3 最小実行体

言語モデル核を実行し、外部入力・結果観測へ接続するために必要な最小runtime。

### 7.4 応用系

- agent harness
- tools
- RAG
- safety classifier
- product routing
- persistent memory service

等。

応用系の能力をmodel coreへ逆帰属しない。
