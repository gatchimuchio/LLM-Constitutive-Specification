## 2. 形成方式

開発元はLLaDAを、自己回帰次token予測とは別の**masked diffusionによるlanguage modeling**として説明する。

生成実装では、

1. prompt後方へMASK状態を配置する。
2. 現在のprompt + 部分生成状態をmodelへ入力する。
3. 各位置・語彙についてlogitsを得る。
4. 候補tokenを形成する。
5. confidence等により一部MASK位置を確定する。
6. 残るMASK位置について再びmodel relationを適用する。
7. 反復して結果列を形成する。

この経路は左から右の単純逐次next-token追加とは異なる。

---

## 3. HDS分別

### 3.1 言語住所規約

外部textをtokenizerにより内部token状態へ接続する。

Instruct版ではchat template等の入力規則を持つ。

この点は自己回帰LLMと上位で共通する。

### 3.2 文脈付き内部言語状態

prompt token + MASK + 途中確定tokenの全体が、現在の形成状態を作る。

モデルは現在状態全体を条件に各位置の形成候補を出す。

### 3.3 模型形成関係

現在の言語状態から、各位置・語彙のlogitsを形成する。

logitsを普遍形式とはしない。

重要なのは、未確定位置について言語状態の形成可能域を作ること。

### 3.4 表出・反復作用

logitsからtoken候補を選び、confidence等により一部を確定し、残りを次の反復へ送る。

従って、

```text
モデル形成可能域
!=
最終言語列
```

がここでも成立する。

---

## 4. 自己回帰型との相対化

### 自己回帰型

```text
既出列
→ 次位置の形成可能域
→ 一位置確定
→ 列へ追加
→ 反復
```

### LLaDA型

```text
prompt + 多数の未確定位置
→ 複数位置の形成可能域
→ 一部位置確定
→ 残りを再形成
→ 反復
```

共通して残るのは、

> **文脈付き言語状態から、未確定言語状態の形成可能域を作り、必要な表出・更新作用を介して言語状態を形成する**

という関係である。

---

## 5. 反証された普遍候補

LLaDAを射程内証人へ追加すると、少なくとも次を現代LLMの普遍必須にできない。

- 左から右
- 1 tokenずつの固定逐次
- autoregressive factorization
- next-tokenのみのformation relation
- KV cache

一方、次は残る。

- 言語住所対応
- 文脈付き言語状態
- 未提示/未確定言語状態への形成relation
- 形成可能域
- 形成可能域と最終表出の非同一
- 同一モデルrelationの反復/再利用

---

## 6. 「確率分布」について

LLaDA自身はprobabilistic modelingを採用する。

しかし、この観測から「確率分布」をLayer-0普遍形式へ昇格しない。

今回確認できるのは、LLaDAでもモデル中核が未確定言語状態の候補差を形成する、という範囲までである。

非確率的実装候補は別反例で監査する。

## 7. 現在中核への適合

現在候補:


ただし実装は自己回帰型と異なる。

従ってこの中核候補は、少なくとも自己回帰固有形式を一段抽象化できている。
