# 証拠状態 — 機能適合・内部観測度・運用閉包・規模状態 四軸再圧縮

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 修正理由

前稿では、

- 模型物確認
- 言語形成機能観測
- 言語形成関係成立
- 運用閉包成立
- 大規模資格

の五状態候補を置いた。

しかし、artifactの存在は証拠型であって、言語模型性と同格の成立状態ではない。

状態数を増やしすぎると監査目的を失う。

従って四軸へ再圧縮する。

---

# 1. 言語形成機能適合

## 1.1 問うこと

> **宣言した対象言語関係に対して、候補系が文脈依存の言語形成関係を成立させていると、現在観測から局所的に採用できるか。**

これはblack-boxでも一定範囲を確認できる。

### 状態候補

- 局所適合
- 不適合
- 未確定
- 未観測
- 再開放要

---

# 2. 内部構造観測度

## 2.1 問うこと

> **その形成機能を内部で何が実現しているかを、どこまで直接観測できるか。**

これは言語模型性そのものではない。

### 例

- weight全量実読
- config/code観測
- 開発元技術文書のみ
- API挙動のみ

既存HDSのD4 / D3 / D2 / D1等の観測深度を再利用できる。

### 重要

```text
内部観測度が低い
!=
言語形成機能がない
```

とする。

---

# 3. 運用閉包状態

## 3.1 問うこと

> **外部言語入力から、言語住所接続・形成関係・表出作用を経て、外部言語結果まで現在の環境で閉じるか。**

### 状態候補

- 局所閉包
- 部分閉包
- 不閉包
- 未観測
- 再開放要

runtime failureを言語形成機能不適合へ自動帰属しない。

---

# 4. 規模状態

## 4.1 問うこと

> **対象領域内で、形成関係がどの程度の状態域・関係域・共有適用域へ成立するか。**

三観測面を保持する。

- 状態域規模
- 関係域規模
- 共有適用規模

一点普遍閾値を置かない。

---

# 5. 模型物確認の位置

模型物・artifact・hash・config等は、

> **内部構造観測度の証拠**

として記録する。

独立したLLM成立状態にはしない。

---

# 6. 対応確認の位置

対応確認は、

> **言語形成機能適合状態を更新する観測作用**

として置く。

対象論上の対応関係候補と、観測証拠を混同しない。

---

# 7. closed model

例:

```text
言語形成機能適合 = 局所適合
内部構造観測度   = D2
運用閉包状態     = 局所閉包
規模状態         = 高い / profile記録
```

内部weight未公開を理由に機能適合を否定しない。

---

# 8. random open artifact

例:

```text
言語形成機能適合 = 不適合 / 未確定
内部構造観測度   = D4相当も可能
運用閉包状態     = 技術的には動作可能
規模状態         = 物理大でも言語relation規模は不適合
```

これにより「重みが大きい」「実行できる」をLLM性へ自動変換しない。

---

|---|---|
