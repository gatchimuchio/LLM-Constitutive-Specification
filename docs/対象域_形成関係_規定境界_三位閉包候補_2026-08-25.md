# 大規模言語モデル最小成立規定 — 対象域・形成関係・規定境界 三位閉包候補

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 目的

これまでの再定義では、

- 言語住所規約
- 文脈
- モデルrelation
- 形成可能域
- 表出作用

等を分別してきた。

これらを再び「最小component一覧」として横並びにすると、旧Layer-0と同じ誤りを繰り返す。

HDS / Trinityの上位閉包へ合わせ、正本側では、

1. 何を対象とするか
2. 何の関係を成立と呼ぶか
3. その関係をどの規定で閉じるか

の三者へ戻す。

---

# 1. 対象域

## 1.1 定義候補

> **対象域とは、候補モデルが扱うものとして本版で切り出した自然言語状態・文脈・範囲の集合的な場である。**

対象域は、モデル内部stateそのものではない。

外部自然言語について、どの状態差・文脈差を候補モデルの成立判定に使うかを定める側である。

---

## 1.2 本版の原対象域

本版では、2026年8月時点の現代運用型大規模言語モデル群を基準に、**人間自然言語の文脈付き状態域**を原対象とする。

コード・画像・音声等は、原対象規定が閉じた後に派生適用する。

---

## 1.3 対象域が必要な理由

対象域を置かなければ、

- 数値計算器
- 画像分類器
- world fact DB
- 検索サービス

等と、自然言語形成モデルの差を、単なる入出力文字列の有無だけで区別できない。

また、領域特化LLMでは、金融・生医療・コード等の対象範囲を明示できる。

---

# 2. 形成関係

## 2.1 定義候補

> **形成関係とは、現在の文脈付き言語状態に応じて、まだ入力として完成形が与えられていない言語状態の成り立ちを区別する関係である。**

この「区別」は、

- 候補
- score
- ordering
- 適否
- 制約
- singleton
- 復元状態
- 次状態

等として実装され得る。

形式を固定しない。

---

## 2.2 最小形

```text
文脈付き言語状態
        ↓
     形成関係
        ↓
    言語形成可能域
```

ここで、形成可能域は外部文字列でなくてよい。

最終表出は別の運用作用へ分離できる。

---

## 2.3 文脈依存

原対象7系統では、文脈差が形成結果へ作用することに射程内反例がない。

従って、本版の形成関係は文脈依存を含む。

ただし、KV cache、Attention、recurrent state等の特定実装を必須にしない。

---

## 2.4 大規模性との関係

形成関係そのものは狭い言語モデルにも成立し得る。

大規模性は、形成関係が対象域内でどれだけ大きな、

- 状態域
- 関係域
- 共有適用域

へ成立するかとして、規定境界側で資格づける。

---

# 3. 規定境界

## 3.1 定義候補

> **規定境界とは、対象域と形成関係を、特定版で同一性・範囲・採否・大規模性・外周分離まで含めて閉じる運用規則である。**

これは対象世界の絶対法則ではない。

版内で再現・監査するための強い約束である。

---

## 3.2 規定境界が持つもの

最低限、次を含む。

### 対象同一性

- 候補名
- 版
- 時点
- 対象自然言語域
- 観測可能範囲

### 言語同一性

- 外部自然言語と内部住所の対応関係
- モデルrelationが何の言語状態に作用しているか

### モデル同一性

- 同じ形成relationを何として同一版とみなすか
- 物理同一性 / 言語relation同一性 / 運用同一性の分離

### 大規模性

- 状態域規模
- 関係域規模
- 共有適用規模

### 外周境界

- 入力接続
- 実行器
- 表出作用
- 外部知識
- 検索
- 道具
- safety
- agent
- UI
- 形成過程

### 採否

- 成立
- 不成立
- 保留
- 対象外
- 未観測
- 未確定
- 再開放

---

# 4. 三位閉包

本版の最小成立規定候補を、次の三者で閉じる。

```text
対象域
  │
  │ 何を扱うか
  ▼
形成関係
  │
  │何を成立させるか
  ▼
規定境界
  │
  └─同一性・範囲・大規模性・採否・外周
```

より正確には、直列ではなく相互拘束である。

```text
        対象域
       ↙     ↘
形成関係 ↔ 規定境界
```

三者のどれかを欠くと、

- 何についてのmodelか
- 何をmodelしているか
- どこまでを同じ成立として読むか

のいずれかが閉じない。

---

# 5. これは三componentではない

対象域・形成関係・規定境界を、

- 3 class
- 3 file
- 3 neural module
- 3 runtime stage

として実装することを要求しない。

これは**成立規定の三つの必要区別**である。

一つの物理artifactが複数区別を担ってよい。

複数artifactが一つの区別を共同で担ってよい。

---

# 6. artifactの位置

モデルartifactは形成関係を有限成立物として保持・実現する証人である。

ただし、artifact単体から、それが自然言語形成relationであることは自動的に決まらない。

外部自然言語との対応を対象域・規定境界から確認する必要がある。

従って、

```text
artifact ≠ 言語モデル性そのもの
```

とする。

---

# 7. 言語住所規約の位置

言語住所規約は独立第4componentではない。

> **対象域とartifact内部状態を対応づけ、形成relationを自然言語relationとして同定するための規定境界上の対応関係**

と置く。

物理的にはtokenizer等として外にあっても、中にあってもよい。

---

# 8. 表出作用の位置

表出作用は、形成可能域から外部結果を確定する運用関係である。

モデル成立核と概念上分離する。

ただし、運用型生成LLM全体を対象にする監査では、

```text
対象域接続
→ 形成relation
→ 形成可能域
→ 表出作用
→ 外部言語結果
```

の閉路を別途確認する。

これをモデル中核成立と同一視しない。

---

# 9. 形成過程の位置

学習・後学習・蒸留・手書き・コンパイル・探索等は、形成relationを持つartifactがどう作られたかを記録する時間的履歴である。

規定境界へ履歴として接続するが、形成relationそのものの普遍形式とはしない。

---

# 10. 大規模性の位置

大規模は形成relationとは別の作用ではない。

> **対象域に対する形成relationの適用規模を資格づける規定**

として置く。

領域特化モデルを除外しない。

汎用性は大規模性と別能力軸へ置く。

---

# 11. 最短候補

日本語だけで最短化すると、現在の候補は次である。

> **大規模言語モデルとは、定めた自然言語対象域について、文脈に応じた未提示言語状態の形成関係を大規模に保持・適用する有限モデルである。**

ただし、

- 「自然言語対象域」
- 「文脈」
- 「未提示言語状態」
- 「形成関係」
- 「大規模」
- 「有限モデル」

の語義は規定境界で別途閉じる。

---

# 12. 次の監査

1. 「有限モデル」を正本定義へ残す必要があるか。
2. 対象域と規定境界を統合できるか。
3. 形成relationを一関係で本当に閉じられるか。
4. 「大規模」を成立規定へ含めるか、別資格規定へ完全分離するか。
5. 運用生成閉路とmodel成立の二段構造を正本へ昇格するか。
6. 原対象7系統＋専門特化LLMへ逆適用する。
