# Layer-0 言語対象とモデル射影の分離 — 2026-08-25

## 状態

`WORKING / NOT_CANONICAL / REOPENABLE`

本書は、Language Modelの対象である言語関係と、モデル内部に保持された有限なmodel relationを同一視しないための境界を定める。

---

# 1. 発火した問題

前段では、

> 言語状態域に存在する言語上の規則的関係を、再利用可能なモデル関係として保持するもの

を最小核候補とした。

しかしこの表現は、

```text
対象側の言語関係
=
モデル内部の関係
```

と読める危険がある。

これはモデルを対象そのものへ昇格させる誤投影である。

---

# 2. 必ず分ける三面

## T — 言語対象契約

モデルが何についてのmodelかを宣言する。

少なくとも、

- language_scope
- target_state_domain
- target_relations
- boundary
- exclusions

を持つ。

`target_relations`は、例えば、

- 状態間の条件関係
- 系列関係
- 構造関係
- 文法関係
- 意味関係
- 候補適合関係
- 復元関係

等を含み得る。

特定の言語学理論へ固定しない。

## M — モデル射影

Tを有限なartifactとして表したもの。

- weights
- rules
- tables
- graphs
- programs
- compiled relations
- hybrid

等。

MはTそのものではない。

未観測・損失・近似・偏りを持ち得る。

## C — 対応／適合

MがTの宣言relationをどこまで保持・再現・利用できるかを観測する。

Cはmodel artifactそのものではなく、model-target correspondenceの監査面である。

---

# 3. Language Modelの最小候補を修正する

## 旧候補

```text
M1 言語状態域契約
M2 再利用可能なモデル関係
```

## 修正候補

```text
T 言語対象契約
M 有限モデル射影
C 対応適合
```

ただしT/M/Cを三つのphysical componentとして要求しない。

Language Modelの意味は、

> **言語対象契約Tに対する有限モデル射影Mが存在し、その対応Cが宣言scopeで成立しているmodel。**

とする方が、対象とモデルの分離を保てる。

---

# 4. random model問題

random-weight Transformerは、

- Tを宣言できる
- Mも存在する

しかしCが成立しない。

従って、

```text
MODEL_ARTIFACT_EXISTS = yes
LANGUAGE_MODEL_CONFORMANCE = fail/suspend
```

となる。

これでarchitectureとfunctionを分離できる。

---

# 5. exact retrieval問題

巨大QA tableも、

- T: question→answer
- M: lookup table

を持つ。

しかしそのTが**言語対象関係**なのか、世界知識instance対応なのかを分ける必要がある。

質問文と回答文が言語だからといって、relation自体がlanguage relationとは限らない。

従ってTには、

```text
modeled_relation_kind
```

を持たせる。

例:

- linguistic_relation
- cross_linguistic_relation
- world_knowledge_relation
- task_label_relation
- arithmetic_relation
- multimodal_relation

等。

これを固定enumとして永久化せず、開放型分類として扱う。

`world_knowledge_relation`や`arithmetic_relation`を言語表面で包んだだけではLanguage ModelのTとはしない。

---

# 6. parser / grammar / translation

## grammar

Tが言語内部の構造relationである。

Mがそれを保持しCが成立するならLanguage Modelの広義候補。

## parser executor

executorはMを適用するX/runtimeであり、grammar model artifactそのものとは分離する。

## translation

source language stateとtarget language stateの対応を対象とする。

これは`cross_linguistic_relation`としてLanguage Model関連modelである。

ただし、単純translation mappingだけをmonolingual LM identityへ自動統合しない。

必要なら、

- Language Model
- Cross-Language Model
- Language Transformation Model

等をrelation scopeで分類できる。

---

# 7. multimodal境界

image→text relationは、入力または出力にlanguageがあるだけで`linguistic_relation`とは限らない。

Tが、

```text
image_state -> language_state
```

だけならmultimodal mappingである。

一方、model内部に、

```text
language_state × prior_language_state -> language_candidate
```

等のlanguage relation submodelが存在するなら、そのsubrelationをLMとして分離監査できる。

Apertus 1.5のHDS観測では、vision/audio前段と中央text decoderを分離して記述できるため、この境界と整合する。

closed multimodal系は内部topology未観測ならSUSPENDする。

---

# 8. MINIDORAへの厳しい帰還

この新境界では、MINIDORAを自動的にLM PASSにしない。

現行MINIDORAは、

```text
自然言語
-> HDS Compiler
-> semantic/world relation state
-> K/C/J
-> result
-> language surface
```

という系に見える。

ここで中央M2相当が主に、

- world knowledge relation
- task relation
- decision relation

を扱い、**言語対象relation自体をモデルしていない**なら、MINIDORAはLanguage ModelではなくLanguage-mediated semantic reasoning systemである可能性がある。

これは新Layer-0をMINIDORAへ合わせて歪めないため、正式な反例候補として保持する。

従ってLayer-0 v5確定後、MINIDORAについて次を独立監査する。

1. T: 何を言語対象relationとしてmodelしているか
2. M: そのrelationをどのartifactが保持するか
3. C: そのrelationが外部未知入力で再現されるか
4. HDS CompilerはT/M/Cのどこに属するか

もしT/M/Cが閉じなければ、MINIDORA自体を再設計する。

---

# 9. 対象関係と世界知識を分離する

Language Modelの`language target relation`と、世界知識Kを混同しない。

```text
Language Modeling Relation
!=
World Knowledge Store
```

世界知識は、

- parameters
- external R
- retrieval DB
- memory
- compiled facts

等へ置ける。

知識量の多寡をLanguage Model identityへ戻さない。

---

# 10. 現時点の判定

- 言語対象relationとmodel relationの分離: **必須**
- model relationを言語そのものへ昇格: **禁止**
- T/M/Cの三面監査: **強く支持**
- T/M/C = 3 physical components: **主張しない**
- QA tableを言語表面だけでLM扱い: **否定**
- grammar relationを名称だけでLM外へ追放: **不採用**
- multimodal output=textだけでLM扱い: **否定**
- MINIDORAを新定義へ合わせて自動PASS: **禁止**

このT/M/C分離をv5最終候補へ統合する。
