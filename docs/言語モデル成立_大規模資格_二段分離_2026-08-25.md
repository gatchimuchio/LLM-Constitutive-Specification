# 言語モデル成立・大規模資格 — 二段分離

状態: 作業中 / 非正本 / 再開放可

日付: 2026-08-25

---

## 0. 結論候補

大規模言語モデルの語を、単一の不可約カテゴリとして定義しようとすると、

- 言語モデルとして何をしているか
- どの程度の規模か

が混線する。

現時点では、次の二段分離が最も説明力が高い。

```text
言語モデル成立
×
大規模資格
=
大規模言語モデル
```

ここで「×」は物理的な二componentを意味しない。

二つの独立した判定面を意味する。

---

# 1. 言語モデル成立

## 1.1 中核

> **定めた自然言語対象域について、対象言語関係に対応する文脈依存の形成関係を保持・適用すること。**

現代運用型生成LLMを原対象にする場合、対象言語関係の中心は、

> **現在の文脈付き言語状態と、未提示言語状態の形成可能性との関係**

として切り出す。

---

## 1.2 言語モデル成立に含めないもの

- パラメータ数
- 学習データ量
- GPU数
- 汎用性
- 多領域性
- 製品利用者数
- 外部tool数

これらは言語モデルrelationの種類そのものではない。

---

# 2. 大規模資格

## 2.1 定義候補

> **大規模資格とは、言語モデルrelationが対象域内で持つ状態・関係・共有適用の規模について与える程度資格である。**

大規模は別のruntime作用ではない。

---

## 2.2 三観測面

### 状態域規模

扱う言語状態の種類・粒度・長さ・組合せの規模。

### 関係域規模

扱う文脈・依存・照応・継続・復元・変換等のrelationの種類・距離・階層の規模。

### 共有適用規模

同一言語モデルrelationを、対象領域内のどれだけ多数の異なる状態・文脈・組合せへ共有適用できるか。

---

# 3. 汎用性を分離する

大規模資格と汎用性は別である。

金融、生医療、code等へ特化した大規模言語モデルが成立する。

従って、

```text
大規模 = 多領域
```

を禁止する。

汎用性は別能力profileとして記録する。

---

# 4. 物理規模を分離する

パラメータ数、総weight量、active parameter数、rule数、table entry数、graph node数等は、実装ごとの物理規模証拠である。

重要だが、異種実装を跨ぐ単一普遍尺度へ自動変換しない。

DenseとMoEだけでも、総parameter数と一回のactive parameter数が異なる。

非ニューラル候補まで含めれば、parameter数自体が存在しない場合もある。

---

# 5. 一点閾値

現時点の観測から、

> この一点以上ならLarge、この一点未満ならLargeではない

という自然な普遍閾値は得られていない。

従って正本候補では、

- 大規模資格は程度・profileである
- 一点普遍閾値は未規定

と明示する。

---

# 6. ではLLM判定は二値でないのか

言語モデル成立はカテゴリ判定として比較的閉じられる。

大規模資格は程度判定である。

従って、`Large Language Model`という通常語の境界には、一定の慣用・時代・比較集合依存が残る可能性がある。

本規定は、この曖昧さを偽の普遍数値で消さない。

代わりに、

1. 言語モデル成立
2. 大規模profile
3. 比較対象集合
4. 版・時点

を明示する。

---

# 7. 現代LLM参照集合

2026年8月の参照集合として、Llama 3 / K2-V2 / OLMo 3 / Apertus 1.5 / Qwen3.6 / DeepSeek V4 / Kimi K3等を置ける。

候補の大規模profileをこの参照集合と相対化することはできる。

ただし、参照集合を永続普遍閾値へ昇格しない。

時代が変われば再開放する。

---

# 8. 最短構造

```text
【言語モデル性】
対象言語relation
    ↕
模型形成relation

【大規模性】
そのrelationの適用規模
```

大規模言語モデルは、両方を同時に記述した呼称である。

---

# 9. Layer-0への帰結

Layer-0のモデル成立核へLargeを独立componentとして入れない。

Layer-0正本候補は、

- 言語モデル成立規定
- 大規模資格規定
- 運用閉包規定
- 形成履歴規定
- 外周境界規定

を分離して持つ方がよい。

これにより「LLM」という一語が異なる階層を再び横並びにすることを防ぐ。

---

# 10. 次の監査

1. 言語モデル成立を一関係まで圧縮できるか。
2. 大規模三観測面は独立に残すべきか。
3. 2026参照集合によるrelative qualificationを機械判定へ使うか。
4. 通常語LLMと本規定の厳密状態語を分けるか。
5. 「大規模」という語自体を正本から外し、別profileへ完全分離する案との比較。
