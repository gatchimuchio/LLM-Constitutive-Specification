# Layer-0 言語閉包と最小関係 再監査 — 2026-08-25

## 状態

`WORKING / NOT_CANONICAL / REOPENABLE`

本書は、2責任候補「言語文脈状態＋モデル作用」をさらに監査し、責任数の最小化ではなく、**何の関係が成立すればLanguage Modelなのか**を取り直す。

---

# 1. 2責任候補の欠陥

2責任候補は次であった。

1. 言語文脈状態
2. モデル作用

しかしこのままでは、次を過包含し得る。

- 感情分類器
- 自然言語calculator
- 一般構文解析器
- exact retrieval

理由は、「言語を入力に使うこと」と「言語そのものの成立関係をモデル化すること」の境界が弱いからである。

従って、責任数ではなく**言語域の閉包**を見る。

---

# 2. 最小核候補を「関係」として置く

現時点の最小候補は、物理component数ではなく次の関係である。

```text
現在の言語状態 L_t
        ×
再利用されるモデル関係 M
        ↓ 実行作用 A
新しい言語状態・言語関係・言語評価 L_(t+1)
```

ここで重要なのは、入力と結果の表面が文字列かどうかではない。

**作用前後の状態が、言語の単位・関係・順序・構造・意味・候補等へ追跡可能に接続されていること**を要求する。

この条件を本書では暫定的に **言語閉包** と呼ぶ。

---

# 3. 三つの論理役割

## R1. 言語状態域

言語上の差異を内部で区別できる状態域。

例:

- token / token列
- hidden state
- masked state
- recurrent state
- 構文状態
- HDS座標・関係
- semantic fact
- linguistic candidate set

重要なのは形式ではなく、言語差が状態差として保持されること。

## R2. モデル関係

複数入力へ再利用され、対象版のmodel identityを保持する、言語状態間の規則性・対応・評価関係。

例:

- neural weights
- n-gram条件表
- grammar rules
- compiled relation set
- symbolic rule base
- MINIDORAの言語基底・K/P等

形成方法は問わない。

`trained / authored / compiled / induced / searched / hybrid` を許容する。

## R3. 実行作用

現在の言語状態へモデル関係を適用し、新しい言語接続状態・関係・評価を形成する作用。

例:

- forward pass
- recurrent update
- attention / KDA / MLA
- diffusion denoising
- rule evaluation
- graph traversal
- conditional table evaluation
- MINIDORAのK/C/J処理

---

# 4. R1/R2/R3は「3 components」を意味しない

物理的には一つの構造が複数役割を担ってよい。

例えばneural networkでは、weightと演算graphを一体の関数として扱える。

一方、MINIDORAやrule systemではmodel relationとinterpreterが明確に分離する。

従って、

```text
論理役割数 != physical component数
```

とする。

Layer-0が固定すべきなのはcomponent数ではなく、**言語状態・model identity・適用作用の関係が失われないこと**である。

---

# 5. 言語閉包条件

Language Model core候補は最低限、次を満たす。

## LC1. 入力側言語接続

現在状態が言語の差異・関係へ追跡可能である。

言語が単なる外装で、coreへ入った直後に非言語task stateへ完全に変換され、その後のmodel作用が言語関係を利用しない場合は弱い。

## LC2. モデル関係の再利用

同一versionとして追跡可能なmodel relationが複数の言語状態へ再利用される。

一入力専用の固定responseをmodel identityとしない。

## LC3. 言語域内の結果形成

作用結果が、少なくとも次のいずれかとして言語へ再接続できる。

- 言語単位候補の評価
- 言語状態の更新
- 言語関係の形成
- 言語構造の形成
- 言語意味状態の形成
- 言語候補集合の更新

単に外部task labelや数値だけを返すことを、これだけでLanguage Modelの証拠とはしない。

## LC4. 完成個体のexact retrievalだけでは閉じない

現在入力と同一keyに対応する完成済みresponseを、そのまま取り出すだけの系は中心例から除外する。

ただしtableという保存形式自体は除外しない。

n-gramのように、tableを使って**現在言語状態に対する候補評価**を形成する系はmodel relation候補である。

# 6. 反例再監査

## 6.1 sentiment classifier

```text
言語入力
→ encoder
→ 固定task label
```

encoder内部にLanguage Model coreが存在する場合、そのencoder部分は別途LM候補となる。

しかしclassifier headまで含む最終task systemの主結果域は固定labelであり、それだけをLLM identityへしない。

**system内にLMが含まれることと、system全体がLMであることを分ける。**

## 6.2 calculator

```text
自然言語
→ parse
→ arithmetic state
→ arithmetic operation
→ number
→ 表面化
```

中央作用対象が算術状態であり、言語関係はinterfaceに退く。

従ってcalculator全体はLanguage Model coreではない。

ただし前段parserが独立したlanguage-modeling relationを持つ場合、その部分は別評価する。

## 6.3 parser / grammar

構文解析・文法規則は、言語域内で言語構造を形成するため、Language Model coreに近い。

ここを名称だけで排除しない。

狭いparserとLarge Language Modelの差は、Coreではなく後述の**言語域幅・関係多様性・組合せ開放性**へ送る。

## 6.4 exact retrieval

完成文書・完成回答をkeyで返すだけならLC4で縮退する。

retrieval結果を現在文脈と合成し、候補評価・関係形成・新状態形成を行う場合はmodel作用候補になる。

## 6.5 unigram

unigramはcontext-freeでも、言語候補に対するglobal evaluationを持つためLanguage Model coreの最小例になり得る。

従って「文脈が必須」はLanguage Model一般には置かない。

ただしLarge profileの文脈関係幅は極小になる。

## 6.6 n-gram

有限contextに対する言語候補評価を形成するため、Language Model core候補。

巨大化してもcontext orderや関係多様性が有限であることはLarge profile側で記録する。

## 6.7 BERT / encoder-only

外部自由生成を必須としない。

masked-token evaluationやcontextual representation形成により言語閉包を持つ場合、LM core候補として扱える。

`text emission`をcore必須にしない。

## 6.8 diffusion LM

masked/noised linguistic stateから反復的にlinguistic stateを復元・評価できる。

従って autoregressive / next-token / left-to-right を必須にしない。

# 7. 旧F1/F2/F3の再配置

2026-02系の旧不可約仕様では、

- F1 内容依存情報検索
- F2 内部知識保持
- F3 十分な直列深度

を存在条件とした。

今回の再監査では、これらを**Core existence conditionから外す**方向が強い。

## F1 内容依存情報検索

高度なLLMでは強力な能力だが、unigram等のLM一般には必須でない。

→ `Capability / Efficiency Profile`

## F2 内部知識保持

MINIDORAのようにData/Knowledgeを外部Rへ分離する実装を先験排除する。

言語関係modelと世界知識保存量は別。

→ `Knowledge Profile / Construction Profile`

## F3 十分な直列深度

複雑な推論・変換の能力には重要だが、任意の言語関係を一段の大きな作用へcompileした実装を原理的に排除できない。

→ `Compute Depth / Capability Profile`

旧観測は破棄せず、**存在条件という帰属だけを変更する**。

# 8. Largeの再整理

LargeはCore作用ではない。

しかし単なるparameter数でもない。

現時点では、次のprofile群が説明力を持つ。

1. **状態域幅** — どれだけ多様な言語状態を扱えるか
2. **関係多様性** — 語彙・構造・意味・談話等、異なる関係種別へ同じcoreを再利用できるか
3. **組合せ開放性** — input-output完成対を全列挙せず未列挙組合せへ作用できるか
4. **文脈関係幅** — 距離・階層・履歴・条件の広さ
5. **領域横断性** — task/domainごとにcoreを交換せず利用できる範囲
6. **結果域開放性** — 固定label/templateへ閉じないか
7. **有効計算深度** — 一回または反復で形成可能な関係変換の深さ
8. **知識依存分離** — 世界知識量とlanguage modeling能力を混同しない

ここから `Large = parameter threshold` は採用しない。

# 9. 新しい層分離候補

```text
Layer-0  言語モデル核
         R1 言語状態域
         R2 モデル関係
         R3 実行作用
         + 言語閉包 LC1-LC4

Layer-L  Large / Language-domain profile

Layer-C  Capability profile
         選択的参照
         記憶・知識利用
         有効計算深度
         推論・合成能力

Layer-T  Compute topology
         系列方向 / 深さ方向 / 幅方向 / 未来補助

Layer-F  Formation / Construction

Layer-O  Operational wrapper / serving

Layer-A  Application / Agent system
```

この分離により、

- `何であるか`
- `どれだけ広いか`
- `何ができるか`
- `どう実装したか`
- `どう作ったか`
- `どう展開したか`

を混同しない。
