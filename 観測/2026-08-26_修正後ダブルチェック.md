## 2. 修正点1 — 自然言語限定を解除

### 旧問題

旧正本は「自然言語状態」を普遍対象としていた。

### 裏取り

Code Llamaは開発元論文で明示的に「large language models for code」とされる。コード補完・infilling・長文脈等を扱うため、LLMを自然言語だけへ限定すると正当な実在LLMを過排除する。

### 修正

対象を「明示した言語体系」へ変更した。

自然言語を中心例としつつ、プログラム言語その他の明示された言語体系を含める。

### 判定

修正後: 適合。

## 3. 修正点2 — 保存追従・破壊追従を成立条件から降格

### 旧問題

意味を保つ言い換え等で模型側の差が保存されることを一律必須にすると、prompt wordingへ敏感な実在LLMをLLMではないと判定し得る。

### 裏取り

Prompt Sensitivity研究では、意味保存的なprompt差でもlog probabilityや出力挙動が大きく変わり得ることが報告されている。

これは頑健性・安定性の問題であり、LLMという成立カテゴリそのものの否定ではない。

### 修正

成立確認の最低限の証拠を、

1. 差分追従
2. 複数対照への再利用
3. 再現性

へ限定した。

保存追従・破壊追従・追加摂動等は補助証拠へ移した。

### 判定

修正後: 過剰条件を除去。

## 4. 修正点3 — 名称と射程をLLMへ整合

### 旧問題

「言語模型成立規定」という名称のまま文脈依存を中心条件にすると、unigram等を含む広義のLanguage Model一般との衝突が起こる。

### 修正

正式対象を「大規模言語模型」に固定した。

広義のLanguage Model一般を歴史横断で定義する文書ではないことを明示した。

### 判定

修正後: 射程整合。

## 5. 非自己回帰系との突合

LLaDA / iLLaDAはmasked diffusionによるlarge language modelであり、自己回帰factorizationを必須としない。

現行規定は「文脈付き内部状態から未確定言語状態に対応する成立差を生じさせる模型側関係」と規定するため、自己回帰固有条件なしで記述できる。

判定: 適合。

## 6. 双方向masked language modelingとの突合

BERT系のmasked language modelingは、周辺文脈から欠損位置の候補差を形成する。

外部自由文生成を必須にしない現行規定で記述できる。

判定: 適合。

## 7. 非Transformer系との突合

RWKVはTransformer標準構造とは異なる再帰的実行形を持ちながら大規模なsequence modelとして成立する。

MINIDORA内横断資料でも、Llama、Qwen、OLMo、DeepSeek、Kimi K3等で系列方向・深さ方向・幅方向の実装が大きく異なる。

現行規定がTransformer / Attention / MoE / 特定残差形式を普遍必須へ置かないことと整合する。

判定: 適合。

## 8. 領域特化との突合

BloombergGPTは金融特化のLLMであり、Code Llamaはコード特化である。

したがって「大規模 = 汎用 / 多領域」ではない。

現行の規模三面と、汎用性を別能力へ置く規定は維持できる。

判定: 適合。

## 9. MINIDORA内HDS横断資料との突合

HDS横断観測では、

- Llama 3: dense + global causal attention
- Qwen3.6: linear/recurrent系とfull attentionの周期 + MoE
- OLMo 3: sliding-windowとfull attentionの周期
- DeepSeek V4: local/long-range系列作用 + mHC等の深さ方向作用
- Kimi K3: KDA / MLA / AttnRes / MoE等

のように、個別構造が大きく分岐する。

一方で、実装名を越えて、文脈付き言語状態の差が未確定言語状態の成立差へ作用するという上位関係は維持できる。

判定: 現行抽象と整合。

## 10. 最終判定

修正後の現行規定について、今回確認した範囲では、正当な実在LLMを構造上排除する射程内反例は確認されなかった。

維持する中核:

```text
候補模型から独立して固定した対象言語関係
        ↕
      局所対応
        ↕
文脈付き内部状態から成立差を生じさせる再利用可能な模型側関係
```

大規模性は、状態域規模・関係域規模・共有適用規模として別記述する。

生成運用性・形成履歴・利用外周・個別architectureは中核成立から分離する。
